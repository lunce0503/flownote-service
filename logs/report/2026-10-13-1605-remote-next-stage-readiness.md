# Remote 다음 단계: 실기기 안정성 검증

## 현재 근거

- 2026-10-12 사용자가 Android 앱에서 서버 연결 성공을 보고했다.
- 2026-10-13 사용자가 Remote CLI가 잘 작동하는 것 같다고 보고하고 다음 단계 진행을 요청했다.
- 이 보고는 접속 및 기본 CLI 동작의 사용자 확인으로 기록한다. 기기/Android/IME 버전, 한글 조합, 회전, 재접속, 모델 API 응답 및 장시간 안정성까지 통과한 것으로 확대하지 않는다.
- 현재 공개 APK는 `remote-android-v0.1.0` 사전 릴리즈, Host는 `remote-host-v0.2.0`이다.
- 서버 상태 확인 시 Host running=true, activeDeviceId=null, session=null이었다. 현재 세션이 없다는 사실은 이전 사용자 접속 보고와 모순되지 않으며, 이전 세션의 명령/출력은 수집하지 않았다.
- 원본 첨부 보고서의 임시 파일은 현재 존재하지 않는다. 저장소에 보존된 [수용 시험](../../apps/android/ACCEPTANCE.md), [제품 사양](../../docs/product-specs/remote-android.md), [APK 배포 결과](2026-10-09-1140-remote-android-apk-release.md)를 기준으로 이어간다.

## 선택과 성공 기준

사용자에게 안정성 검증/모바일 UI/QR 등록 중 우선순위를 질문했다. 응답 전에도 가능한 기존 기준 확인을 진행했으며, 기본 다음 단계는 실기기 안정성 검증과 정식 릴리즈 준비로 정한다. 다른 우선순위 답변이 오면 해당 범위를 먼저 구체화한다.

성공 기준은 실제 휴대폰에서 입력·화면·세션 복구·장시간 사용 결과가 항목별로 남고, 재현되는 오류를 수정해 자동 회귀 검증 및 APK 검증을 통과하는 것이다. 아래 시험이 끝나기 전에는 사전 릴리즈를 정식 안정 릴리즈로 전환하지 않는다.

## 진행 순서

| 단계 | 작업과 판정 | 현재 상태 |
| --- | --- | --- |
| 1. 기본 접속 | 실제 앱 등록/접속, PC CLI 사용 | 사용자 기본 동작 확인. 상세 기기 정보 미수집 |
| 2. 입력·화면 | 한글 IME 직접 입력/명령 입력창, Tab/방향키/Ctrl+C/붙여넣기, 세로·가로 및 키보드 표시 | 상세 실기기 결과 대기 |
| 3. 일시 단절 | 백그라운드 복귀와 VPN 단절/복귀 10회, 동일 세션 및 입력 중복 없음 | 실기기 결과 대기 |
| 4. 복구·종료 | 앱 강제 종료 후 새 세션 안내, 재생 범위 초과, 명시 종료·유예 만료·Host 종료와 자식 프로세스 정리 | 실기기 결과 대기; 사용자 세션을 임의 중단하지 않음 |
| 5. 장시간 | 30분 사용, 세션 수 및 Host/앱 메모리 비교, Codex 대화형 동작 | 실기기 결과 대기 |
| 6. 정식 준비 | 재현 오류 수정/회귀 검증, 동일 소스의 Android CI 및 서명 APK 검사, 결과와 설치 안내 갱신 | 이전 단계 이후 |

실기기 시험은 [ACCEPTANCE.md](../../apps/android/ACCEPTANCE.md)의 전체 조건을 유지한다. 위 표는 우선순위 요약이며 인증 실패, 토큰 폐기, 동시 클라이언트, Windows 호환성 등 나머지 조건을 삭제하거나 면제하지 않는다.

## 영향 범위와 구현 경로

- `apps/android/`: 입력/화면 문제일 때만 `RemoteApp.kt`, `TerminalView.kt`, `terminal.js` 및 대응 테스트를 수정한다.
- `apps/host/`: 세션 수명/프로세스/출력 재생 문제일 때만 해당 모듈과 테스트를 수정한다.
- `protocol/remote-host/v1/`: 현재 v1 계약을 유지한다. 계약 변경이 필요하면 Android·Host 양쪽과 스키마 검증을 함께 반영한다.
- QR 등록, 다중 PC, 파일 관리 및 인터넷 릴레이는 이번 안정성 검증에서 새로 구현하지 않는다. 범위 선택에 따라 별도 작업으로 구체화한다.
- 현재 기기 토큰을 폐기하거나 실행 서비스/사용자 세션을 재시작하지 않았다. 비밀값, 터미널 원문과 인증 환경을 보고서에 기록하지 않는다.

## 이번 검증

- `npm run typecheck --prefix apps/host`: 통과, 소스 생성 없음.
- `npm test --prefix apps/android/terminal`: 7개 통과.
- Host 상태 및 GitHub 릴리즈 목록 확인: 서버 실행 중, 위 버전/사전 릴리즈 상태 확인.
- 새로운 Android 에뮬레이터/실기기 검증이나 모델 API 호출을 실행한 것으로 표시하지 않는다. 기존 CI 통과 근거는 APK 배포 보고서를 참조한다.

이번 변경은 `logs/report/` 기록만 추가하므로 문서 및 diff를 검증하고 Docker 빌드와 클라우드 배포를 생략한다. 실행 코드·APK가 바뀌지 않아 새 APK 태그나 Railway/Vercel 배포는 만들지 않는다.
