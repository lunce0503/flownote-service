## 범위와 안전성

영향은 공유 Vite 웹 `flownote/`이며 iOS/iPadOS 등 설치 앱도 같은 웹을 사용한다. 서버 API/DB migration/인증 계약/의존성/자동화 권한/일간 타이머는 변경하지 않는다. 기존 대규모 사용자 변경을 되돌리거나 전체 과거 후보 patch로 덮지 않았다. `flownote-remote`는 제외한다.

포인터는 장식 요소로 입력/포커스를 받지 않고 기존 필기·이동·핀치·Pencil 두 번 탭을 유지한다. OFF의 서버 전송 금지와 계정 구분을 유지하며 원본/초안/큐를 삭제하지 않는다. NEW는 24시간 경과 뒤 화면 배지만 숨기며 처리 완료를 위장하지 않는다. 보안/API/UX 스킬을 이 경계 확인과 모바일·실제 저장 회귀에 적용했다. TDD 스킬에 따라 새 테스트의 실패를 먼저 확인한 뒤 구현했다.

## 앱 관리 인계

`docs/operations/app-release-handoff.md`에 따른 기존 세션 `01a04858-b6df-7613-91da-c92a37955657`(`application manage`/`flownote 앱 관리`)에 사용자 원문과 3건 범위·과거 OAuth 실패를 전달했다. 처음에는 소스 수정/배포 없이 읽기 전용 사전 점검을 요청했다. 수신 세션의 실제 도구 실행과 2026-10-24T12:04:39Z 완료 응답을 확인했다.

사전 점검: Railway 인증·프로젝트 조회 정상, 진행 중 로컬 릴리스/대기 GitHub Actions 없음, 기존 웹 READY. 현재 앱 채널은 Android 1.3.0, Windows 1.3.1, iOS 1.3.0(8) 기준이다. 버전·빌드/배포 ID는 담당 세션이 최종 검증하여 기록해야 한다. 새 세션을 만들지 않았다.

최종 구현·검증·소유 문서를 같은 세션에 전달한 뒤 공유 소스를 동결하고 진행을 확인한다. 웹 release는 `node scripts/deploy-cloud.mjs release web` 또는 담당이 준비한 동일 정책 snapshot release로 staging E2E 후 production 순서를 지킨다. 이번 범위에서 네이티브 소스는 변경하지 않았으므로 설치 앱의 공유 웹 반영과 기존 업데이트 경로를 확인하고 새 패키지 필요 여부를 구분한다. 단순 인계 접수나 기존 앱 버전을 새 릴리스 완료로 보고하지 않는다.

현재 운영 배포는 아직 완료되지 않았다. 배포 URL/ID·소스 지문·게이트 결과·메일·실패 큐 정리는 확인 후 아래 갱신한다.
