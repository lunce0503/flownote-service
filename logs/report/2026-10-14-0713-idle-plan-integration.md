# IDLE 계획의 Flownote 편입

작성: 2026-10-14 07:13 UTC.

## 요청과 반영

사용자 요청: “지금 idle의 계획을 flownote에 편입시키자”.

IDLE의 초기 에이전트 루프 계획·현재 아키텍처·데스크톱 후속 계획을 Flownote의 [개발 작업 공간 실행 계획](../../docs/exec-plan/active/2026-10-14-idle-integration.md)과 [제품 사양](../../docs/product-specs/development-workspace.md)에 편입했다. 계획 소유 위치를 Flownote로 정하고 IDLE README와 초기 계획에 연결을 남겼다.

문서 지도·제품 사양 색인·PLANS·active 색인·제품 관점·시스템 설계에도 계획을 연결했다. 기존 사용자 변경은 보존했다.

## 결정

- 실행 계약·기존 결과 조회 → 수동 실행·검토 → 데스크톱 편집기 → 모바일 제어 → 운영 품질·확장 순서로 진행한다.
- 기존 Codex 워커·신뢰 컨트롤러·timer/큐·Remote를 재사용하고, IDLE 코어·프로토콜·도구·편집기는 단계별 선별 이전한다.
- 클라우드 인증은 Flownote 세션, 기준 데이터는 PostgreSQL/Flyway를 사용한다. IDLE의 단일 토큰·SQLite API 서버를 그대로 도입하지 않는다.
- IDLE 코드·기존 릴리즈는 원본으로 보존한다. 이번 변경으로 코드 이전·패키지 변경·실행 API·새 서비스가 완료된 것은 아니다.

## 검증

- 변경 문서 11개에서 상대 링크 26개, 중복 제목, 줄 끝 공백 검사: 오류 0.
- Flownote와 IDLE에서 변경 문서 대상 `git diff --check`: 각각 종료 코드 0.
- 문서 지도·제품 사양·실행 계획·원본 계획의 연결과 단계 상태를 확인했다.

앱 실행 코드가 바뀌지 않아 빌드·단위 테스트·실기기 시험은 실행하지 않았다.

## 배포 범위

사용자가 요청한 계획 편입 범위에 맞춰 문서만 변경했다. 클라우드·데스크톱·APK 실행 산출물 변경이 없으므로 배포, 서비스 재시작, 자동화 실행을 수행하지 않았다. 후속 구현의 배포는 기존 staging-first 기준을 따른다. commit/push는 수행하지 않았다.
