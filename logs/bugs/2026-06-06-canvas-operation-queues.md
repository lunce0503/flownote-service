# 캔버스 작업 큐 분리

## 증상

- 자동 저장과 페이지 이탈 저장이 서로 다른 네트워크 요청을 시작할 수 있었다.
- 저장 중 도착한 다른 사용자 또는 다른 기기의 변경은 단일 boolean으로만 보류되어 적용 순서가 명확하지 않았다.
- 원격 데이터를 다시 불러온 뒤에도 이전 로컬 undo snapshot이 남을 수 있었다.
- 짧은 시간에 상태가 여러 번 바뀌면 동일 프레임 안에서 정적 캔버스를 반복 렌더링할 수 있었다.

## 원인

- `handleFlushSave`가 기존 저장 실행 경로를 통하지 않고 `canvas:save`를 직접 호출했다.
- 원격 변경 보류 상태가 이벤트 큐가 아닌 `remoteReloadRequestedRef` 하나로 관리됐다.
- 히스토리와 원격 데이터 적용 생명주기가 연결되지 않았다.
- Konva 렌더 호출에 프레임 단위 병합이 없었다.

## 수정

- `auto`, `manual`, `retry`, `flush` 트리거를 유지하면서 모든 저장을 하나의 직렬 저장 경로로 통합했다.
- 페이지 이탈 시 로컬 초안과 재시도 항목을 먼저 남기고 동일 네트워크 큐에 저장을 요청한다.
- 원격 변경 알림은 캔버스별 최신 이벤트 큐로 병합하고 로컬 저장이 끝난 뒤 적용한다.
- 원격 데이터 적용 시 스트리밍 표시와 undo 스택을 초기화한다.
- 로컬 캔버스 렌더링은 `requestAnimationFrame` 큐에서 최신 상태 한 건만 렌더링한다.
- undo 히스토리는 최대 50개의 snapshot을 보관하는 스택으로 유지한다.

## 남은 위험

- 서버 응답이 유실된 경우 동일 payload의 재전송을 식별할 멱등성 키는 아직 없다.
- 여러 선을 R2에 저장하는 서버 작업은 여전히 선 단위 동기 업로드 방식이다.
- 원격 변경과 로컬 변경의 필드 단위 병합은 하지 않으며, 로컬 저장 완료 후 서버 최신 상태를 다시 불러오는 방식이다.
