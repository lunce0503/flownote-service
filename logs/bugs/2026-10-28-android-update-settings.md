# Android 하단 업데이트 표시를 설정으로 이동

- 상태: 1.3.1(13100) 구현·통합 전 핵심 에뮬레이터 회귀 PASS. 설치 허용 switch를 강제하는 추가 실행은 통합과 병행한다. 공개 앱/피드 1.3.0(13000)은 그대로다.
- 증상: Android `AppUpdater`가 MainActivity의 세로 LinearLayout에 별도 상태/업데이트 바를 붙여 모든 웹 화면의 가용 높이를 줄인다. 업데이트 조작이 설정과 분리되어 있다.
- 원인: 생성자에서 네이티브 상태 TextView와 Button을 부모에 추가하고, 상태 갱신을 이 두 View에 직접 연결한다.
- 수정: 바를 생성하지 않고 상태를 보관한다. Settings의 전용 카드가 설치 버전·상태를 표시하며 고정 HTTPS 경로를 통해 네이티브 관리 창을 연다. 창에서 수동 확인·설치·변경 내용·이력을 제공한다. 자동 확인/다운로드·서명/해시·채널·rollback 검증·Android 설치 확인은 유지한다.
- 보안: 동일 origin의 `/settings`에서 사용자가 누른 main-frame GET만 허용한다. 임의 URL/경로/파일/인자와 iframe·script-only 요청을 거부한다. 표시용 상태만 native→web으로 전달하고 `JavascriptInterface`는 추가하지 않는다.
- 통합 전 검증: 새 웹을 아직 배포하지 않으므로 실제 후보 컴포넌트를 CDP로 현재 staging 화면에 마운트한다. 이를 staging 배포/전체 통합 gate 통과로 기록하지 않는다. 기존 앱의 하단 업데이트 안내와 새 앱의 설정 창 양쪽을 시험한다.
- 테스트 장치 주의: 첫 실행의 System UI ANR는 기존 API35 에뮬레이터 부팅 환경 문제였다. 시스템 UI를 다시 열고 재실행한다. inline script 테스트 주입은 CSP에 막혀 CDP 실행으로 바꾸며 실제 CSP는 완화하지 않는다. 고정 경로는 native에서 소비되어 탐색 완료 이벤트가 없으므로 테스트는 click의 탐색 대기 대신 native 창과 기존 URL을 직접 확인한다. OS 설치 직후 프로세스 지연 종료를 기다리고 새 프로세스를 다시 여는 방식으로 ADB/CDP 연결을 안정화한다.
- 최종 검증·배포 상태는 같은 작업의 report와 앱 소유 문서를 따른다. 부모의 병렬 소스 통합을 위한 작업 분담에 따라 통합 전 배포를 보류하며 사용자 전체 배포 목표는 유지한다.
