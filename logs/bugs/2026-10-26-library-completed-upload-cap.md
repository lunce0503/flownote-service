# 완료된 책장 업로드가 진행 중 제한을 소비함

증상: 같은 계정이 24시간 안에 네 권의 PDF 업로드를 완료하면 다섯 번째 책 추가가 HTTP 429로 거부된다. 진행 중 업로드는 없는데 먼저 완료하라는 안내가 표시된다.

원인: library_uploads는 중복 완료 요청의 멱등성을 위해 완료 세션도 24시간 보존한다. StartUpload가 만료되지 않은 모든 세션을 세어 완료 receipt도 진행 중 4개 제한에 포함했다.

수정: library_books.upload_id와 소유자가 일치하는 완료 receipt를 진행 중 count에서 제외한다. 완료 영수증은 보존하고 실제 미완료 동시 업로드 네 개 제한은 유지한다. 기존 데이터 마이그레이션 변경은 필요 없다.

검증: library-upload-cap.spec.ts에서 같은 계정의 PDF 여섯 권을 연속 완료한 뒤 미완료 네 개는 허용·다섯 번째는429·기존 세션 resume 허용·첫 완료 재요청의 멱등성을 실제 스테이징에서 검사한다. 등록과 정적 검사만으로 실제 클라우드 통과를 주장하지 않는다. 최종 배포 결과는 workspace-library 실행 계획과 앱 관리 릴리스 보고서가 소유한다.
