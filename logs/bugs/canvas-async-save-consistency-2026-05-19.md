# 캔버스 비동기 저장 일관성

## 증상

- 캔버스에 작성한 요소가 클라이언트에는 보이지만 서버 저장 결과와 달라질 수 있다.
- 저장 요청이 진행 중일 때 추가 작업을 하면 늦게 도착한 저장 응답이 새 변경 상태까지 `unchanged`로 초기화할 수 있다.

## 원인

- 캔버스 저장은 `fetch` 기반 비동기 요청이다.
- 기존 로직은 저장 요청이 시작된 뒤 발생한 변경을 구분하지 않고, 저장 성공 시 모든 요소 상태를 초기화했다.
- 로컬 브라우저에 pending 초안이 보존되지 않아 네트워크 실패나 iPad Safari 페이지 전환 상황에서 클라이언트/서버가 달라질 수 있었다.

## 수정

- 캔버스 상태를 `localStorage` 초안에 먼저 저장한다.
- 저장 요청 중 추가 변경이 생기면 기존 요청 성공 후 상태를 초기화하지 않고 다시 저장을 예약한다.
- 서버 저장 성공 후 서버 데이터를 다시 로드해 클라이언트 스냅샷과 비교한다.
- 불일치하면 클라이언트 스냅샷을 기준으로 서버를 보정하는 reconcile payload를 전송한다.
- 서버 로드 실패 또는 pending 초안이 남아 있는 경우 로컬 초안을 우선 복구한다.

## 검증

- `flownote/`에서 `yarn build` 성공.
