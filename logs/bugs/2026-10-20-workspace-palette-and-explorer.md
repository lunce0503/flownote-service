# 캔버스·노트 디자인 불일치

## 증상과 원인

노트가 파란 선택 배경/남색 다크 표면을 사용해 캔버스의 아이보리·흰색·검정 UI와 달랐다. Markdown workspace CSS가 독립적인 색상 상수를 가지고 있었다. 캔버스 라이브러리는 폴더 안에서도 카드 그리드를 반복해 파일 탐색 방식으로 사용하기 어려웠다. 메뉴·탭·편집기에 그림판/게시글이라는 이전 명칭이 남아 있었다.

## 수정

공용 workspace 색상 변수를 도입해 흰 문서·베이지 탐색/선택·검정 글자/동작을 공유한다. 저장된 테마는 보존하고 다크 모드는 따뜻한 무채색으로 처리한다. 캔버스는 폴더 트리와 상세 파일 목록, 검색·키보드 이름 변경·이동·삭제 확인을 제공한다. 폴더만 지우면 문서는 미분류에 남는다. 실제 API와 저장 데이터·URL은 유지한다. 공개 명칭은 캔버스/노트(영문 Notes)다.

## 검증 중 발견한 사항

첫 staging 전체 실행은 49/52 통과했다. 새 폴더 버튼 때문에 기존 '새 캔버스'의 부분 일치 선택자가 두 버튼을 찾아 실패했다. 이후 Playwright가 worker와 account fixture를 재시작하면서 기존 복사/붙여넣기 검사가 앞선 드로잉 fixture를 잃어 연쇄 실패했다. 신규 명칭 검사도 숨겨진 모바일·데스크톱 버튼을 getByLabel로 함께 찾아 실패했다. 의도한 버튼의 정확한 이름과 visible role을 사용하도록 수정했으며 기능 assertion/timeout을 제거하거나 skip/retry하지 않는다.

화면 검토에서 노트 하단 여백이 캔버스와 달라 shell 높이 기준을 통일하고 설치 앱의 하단/측면 탐색을 고려했다. 최종 전체 staging 재실행·동일 소스 production 결과는 작업 보고서에서 확정한다. 실제 사용자 문서나 production 데이터를 테스트하지 않는다.

두 번째 staging은51/52였다. 생성 버튼/숨겨진 버튼 선택은 해결됐으나, 복사/붙여넣기 흐름의 targetTitle 부분 일치가 파일 열기·이름 수정·삭제 세 버튼을 동시에 찾았다. 해당 파일명과 정확히 일치하는 열기 버튼을 선택하도록 수정했다. 두 번째 이후 실행 코드 변경은 없고 E2E 선택자만 변경했음을 byte 비교로 확인했다.


## 해결 확인

최종 staging 전체52/52 통과 후 동일 소스 운영 배포 완료. 회귀와 변경된 명칭·색상·파일 동작을 검증했다. [완료 보고서](../report/2026-10-20-1144-canvas-note-workspace-design.md).
