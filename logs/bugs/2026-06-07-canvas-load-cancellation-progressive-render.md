# 그림판 불러오기 취소 및 점진 렌더링

## 증상

- 그림판을 전환해도 이전 Socket.IO 불러오기와 Spring API 요청이 계속 실행됐다.
- 이미지 파일이 모두 준비될 때까지 선과 텍스트도 화면에 적용되지 않았다.

## 원인

- 클라이언트는 늦게 도착한 응답의 적용만 막고 진행 중 요청을 취소하지 않았다.
- FastAPI의 Spring 전달이 `asyncio.to_thread()` 기반 동기 HTTP 호출이어서 작업 취소가 하위 요청까지 전달되지 않았다.
- `applyCanvasDraft()`가 모든 이미지를 `Promise.all()`로 준비한 후 전체 상태를 한 번에 적용했다.

## 수정

- 각 불러오기에 `requestId`와 `AbortController`를 부여했다.
- `canvas:load-cancel` 이벤트로 FastAPI 작업을 취소하고, FastAPI의 불러오기 전달을 취소 가능한 `httpx.AsyncClient` 호출로 변경했다.
- 그림판 선택 변경 시 이전 요청을 취소한 뒤 최신 선택을 다시 불러온다.
- 사용자가 툴바의 취소 버튼을 누르면 현재 요청과 예약된 후속 불러오기를 모두 취소한다.
- 선, 텍스트, 이미지 자리 정보를 먼저 적용하고 각 이미지가 준비되는 순서대로 해당 이미지만 갱신한다.

## 검증

- FastAPI 작업 레지스트리 취소 테스트
- FastAPI 전체 단위 테스트
- Vite 프로덕션 빌드
- Docker 통합 빌드 및 서비스 헬스체크
