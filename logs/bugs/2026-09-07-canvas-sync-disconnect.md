# 캔버스 반복 끊김과 제거된 동기화 서비스

## 증상과 근거

- Next SSE 주소가 Vercel `404 DEPLOYMENT_NOT_FOUND`를 반환하며 브라우저에는 CORS 오류로 표시됐다. Next 서비스 제거 후 구독 코드가 남아 있었다.
- Railway API는 연결 수락 후 약 1초 내 연결 종료를 반복했다. 캔버스 metadata는 200이며 유휴 연결 시험은 30초간 유지됐다.
- 운영 Socket.IO handshake의 maxPayload는 1,000,000이다. 같은 Python 라이브러리 설정에서 900KB 메시지는 ack를 받고 1MB 초과는 연결이 닫혔다. 실제 실패한 사용자 payload 크기는 당시 로그에 없어 직접 원인 확정은 불가능하다.
- 재연결 때 저장 backoff를 초기화했고, retryable:false 값도 큐에서 자동 재시도 중단에 반영되지 않았다.
- 새로고침 E2E에서 초기화 전 cleanup/flush가 빈 상태로 IndexedDB 초안을 지우는 추가 문제를 재현했다. 캔버스 초기화 완료 전에는 자동 저장·초안 쓰기·flush를 실행하지 않고, 로드 시작 전에 큐 복원을 기다리도록 수정했다.

## 수정 방향

- 일반 동기화를 현재 게이트웨이의 인증된 Socket.IO namespace로 이전한다.
- 큰 저장은 상한이 있는 HTTP 경로로 보내고 소켓과 같은 mutation/ack/브로드캐스트를 사용한다.
- 영구 오류는 초안과 큐를 보존한 채 자동 재시도를 차단한다. 재연결이 backoff를 초기화하지 않도록 한다.
- 서버는 저장 크기와 소켓 종료 사유를 기록하고 인증 값과 문서 원문은 로그에 넣지 않는다.
- 운영 smoke에서 1.1MB의 잘못된 세션 요청을 Go로 먼저 전달하면 조기 연결 종료가 502로 변환되는 경우를 확인했다. HTTP 본문을 Go에 전달하기 전에 Spring 세션 검증을 수행해 401을 반환하도록 보완했다.
