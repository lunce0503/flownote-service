# 동기화 OFF가 빈 기기 공간을 열고 ON 때 조정하지 않음

## 증상

설치 앱에서 앱 동기화를 끄면 기존 서버 자료가 보이지 않는 빈 기기 전용 공간이 열렸다. OFF 중 작성한 `device-` 자료는 다시 동기화를 켜도 서버로 올라가지 않아 사용자가 수동 내보내기 외에는 다른 기기에서 이어 쓸 수 없었다.

## 원인

기존 v1 작업 공간은 클라우드 기준본·서버 revision·대기 연산을 저장하지 않았고, 전환 로직은 모드 값만 바꿨다. 네트워크 차단은 fail-closed였지만 안전한 조정에 필요한 3-way 기준과 멱등 생성 계약이 없었다.

## 수정 방향과 결과

- v2 작업 공간에 클라우드 스냅샷·기준본·전환 상태·대기 연산 cursor·충돌 복구본을 추가하고 v1/`device-` 자료를 보존한다.
- OFF 성공 전에 전체 지원 자료와 캔버스 이미지를 계정별 IndexedDB transaction으로 저장한다.
- ON 때 최신 서버본과 3-way 조정하고 안정된 UUID·멱등 생성 API·연산 cursor로 재시도한다.
- 같은 값의 충돌은 기준본 이후 구조적 변경량, 최신 수정 시각, 기기본 순으로 결정하고 선택되지 않은 버전을 복구 기록에 남긴다.
- 조정 중에만 메모리 scope가 있는 내부 요청을 허용하며 일반 UI/실시간 네트워크 차단은 유지한다.

실제 배포 ID와 cloud E2E·앱 릴리스 결과는 같은 날짜의 `logs/report/` 완료 보고서에 기록한다.
