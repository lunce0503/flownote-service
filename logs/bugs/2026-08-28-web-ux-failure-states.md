# 웹 UX 실패 상태와 모바일 도구 접근성

## 증상

- 회원가입 API가 실패해도 성공 알림 뒤 로그인 화면으로 이동했다.
- Blog 노트 저장 실패가 1.5초 간격으로 계속 재시도됐고 사용자에게 상태가 보이지 않았다.
- 노트 조회 실패가 빈 목록이나 노트 없음으로 표시됐다.
- 390px 화면에서 노트 제목 입력 폭이 약 60px까지 줄었다.
- 모바일 Canvas의 저장·불러오기·전체 화면·설정이 스크롤 끝에 숨고 스크롤바도 표시되지 않았다.
- 헤더 메뉴와 드로잉 모달을 Escape로 닫거나 키보드 포커스를 관리할 수 없었다.

## 원인

- 회원가입 API 함수가 예외를 삼켰고 호출부가 Promise 완료를 기다리지 않았다.
- Blog 저장 큐에 최대 재시도, backoff, 타이머 정리, 실패 상태 UI가 없었다.
- 노트 조회 함수가 모든 오류를 빈 배열로 변환했다.
- 노트 제목과 동작 버튼이 같은 flex 행의 폭을 경쟁했다.
- Canvas의 모든 도구와 파일 동작이 하나의 가로 스크롤 행에 배치됐다.
- 메뉴와 모달에 Escape, 포커스 이동·복귀, 대화상자 semantics가 없었다.

## 수정

- 회원가입 성공과 실패를 API 응답 기준으로 분리하고 제출 중·오류 상태를 추가했다.
- Blog 저장을 500ms/1초/2초의 최대 3회 재시도로 제한하고 수동 재시도와 서버 버전 복구를 추가했다.
- 노트 API 오류를 호출부에 전달하고 목록·상세 화면에 오류와 다시 시도 상태를 추가했다.
- 모바일 노트 제목과 동작 영역을 별도 행으로 분리했다.
- 모바일 Canvas를 탐색·파일 동작, 그리기 도구, 색상 행으로 분리하고 파일 메뉴를 추가했다.
- 헤더 메뉴와 드로잉 대화상자에 키보드 포커스와 Escape 처리를 추가했다.

## 회귀 테스트

- 회원가입 서버 실패 시 `/signup` 유지와 오류 표시
- Blog 조회 오류와 빈 상태 구분
- Blog 자동 저장 재시도 종료 및 수동 복구 버튼
- 모바일 노트 제목 최소 폭과 Canvas 파일 메뉴
- 헤더 메뉴와 드로잉 대화상자의 Escape 동작
