# 대시보드와 쉬운 연결

0.3.0부터 Windows·Android는 시작 화면에 **소리 / 카메라 / 제스처 / 음성 알림**을 보여 준다. Windows의 서버 시작, QR을 보여 주는 클라이언트 연결, 다른 서버 참여는 주요 행동이다. Android는 QR 읽기·연결 코드·저장된 서버 재연결을 먼저 제공한다.

## 클라이언트 목록

행에는 사용 토글, 기기 이름, 실제 연결된 기능을 요약한다. 카메라 전송·출력 상태/음량·음성 알림 대상·제어 대상을 현재 서버 상태에서 표시한다. 오프라인과 일시 중지, 출력 장치 오류를 구별하며 미구현 화면/음원 처리 기능을 연결됐다고 표시하지 않는다.

- Windows 서버의 토글은 해당 기기의 **서버 사용 허용**이다. 등록 기기가 오프라인이어도 변경하고 저장할 수 있다.
- 연결된 클라이언트는 자기 기기만 일시 중지/재개할 수 있다. 다른 행의 토글은 읽기 전용이며 관리는 서버에서 한다. 서버가 금지한 기기를 클라이언트가 다시 허용할 수 없다.
- 중지하면 카메라·출력 명령을 차단하고 상태 연결을 유지한다. 카메라 전송은 중지하며 재개 후에도 사용자가 직접 켠다. 서버가 허용해도 기기 자체에서 일시 중지한 상태는 강제로 해제하지 않는다.
- 목록의 기기 이름과 메뉴 접근성 이름은 전체 이름을 유지한다. WPF 행과 Android 행을 매 heartbeat마다 다시 만들지 않아 포커스를 보존한다.

화면 상단 `⋯`에는 제스처 세부 설정, 서버 연결 설정, 연결 기록과 상세 정보, 연결 해제/서버 중지, 라이선스를 둔다. 기기의 `⋯`에는 제어 대상 선택·상세 정보, 서버에서는 음성 대상 선택과 등록 해제를 둔다. 등록 해제는 다시 등록해야 하는 동작이므로 앱에서 확인한다.

Android의 기존 제스처 세부 설정은 이 기기의 합성 테스트 설정이다. 실제 인식 정책은 서버 PC가 소유하며 Android에서 저장해도 서버 정책이 바뀐다고 안내하지 않는다.

## QR과 연결 코드

1. PC 서버를 시작하고 **클라이언트 연결**을 누른다.
2. Android/Windows 클라이언트에서 QR 읽기를 선택한다. 카메라는 이 명시적 행동 후에만 사용한다. 서버에 연결되기 전 QR을 읽는 카메라 프레임은 기기 안에서만 처리한다.
3. 읽으면 확인 화면에 주소와 지문이 채워진다. 내 서버 화면의 QR 또는 주소·지문인지 확인하고 **확인하고 연결**을 누른다. QR을 읽는 것만으로 네트워크 등록·명령 실행을 하지 않는다.
4. 카메라를 사용할 수 없으면 PC에서 **연결 코드 복사**, 클라이언트에서 **연결 코드 붙여넣기/가져오기**를 사용한다. 주소·지문·일회용 코드를 직접 입력하는 방법도 세부 화면에 남긴다.
5. 만료되면 PC에서 **새 QR 만들기**를 누른다. QR은 2분·1회용이며 등록 후 장기 기기 토큰을 담지 않는다. Clipboard는 사용자가 붙여넣기를 누를 때만 읽는다.

QR 이미지를 외부 생성/판독 서비스에 보내지 않는다. 주소·인증서 지문은 실제 서버 화면을 통해 전달하고 기존 TLS 지문 검증을 유지한다. 임의 URL이나 셸 명령을 열지 않는다. QR/등록 코드와 토큰은 로그·UX screenshot artifact에 남기지 않는다. Windows QR 창은 남은 시간을 표시하고 만료 시 이미지를 비운다. 앱이 재시작되면 새 등록 코드를 발급한다.

카메라 스캔 취소·권한 거부·연결 실패는 화면에 안내하고 수동 연결을 제공한다. QR 데이터에는 사용자가 신뢰하는 서버인지에 대한 증명이 별도로 들어 있지 않으므로, 실제 내 서버 화면의 QR인지 사용자 확인을 유지한다.

## 레이아웃과 검증

Windows는 넓은 화면에서 기능 카드를 두 열, 좁은 화면에서 한 열로 표시한다. Android는 세로 카드와 행으로 구성한다. 메인 제어와 메뉴에는 접근성 이름을 붙이고 토글은 표준 접근성 Toggle/Checked 동작으로 조작한다. Android 터치 영역은 최소 48dp를 사용한다. 내용은 세로로 스크롤하며 세부 폼도 작은 화면에서 스크롤할 수 있다.

- 공통 QR 입력 벡터는 `tests/fixtures/pairing-links.json`이다. .NET·Android가 만료·공개 IP/HTTP·자격 증명·중복/추가 필드·잘못된 지문/버전을 같은 기준으로 검사한다. 이 벡터는 테스트 전용으로 release APK/EXE에 넣지 않는다.
- 실제 Windows QR 픽셀 생성→판독, Android Bitmap QR 판독→등록 확인을 검사한다. 광학 카메라로 다른 화면의 QR을 읽는 품질은 별도 실기기 항목이다.
- EXE 실행 검사에서 대시보드·`⋯` 설정/라이선스·설정 재시작 복원·클라이언트 중지/재개·QR 패널을 확인한다. 대시보드만 넓은/420px 화면에서 캡처한다.
- Android 10 장치 검사는 320dp 폭·font scale 1.3에서 `⋯` 메뉴, 저장된 연결 재접속, 실제 상태 목록/자기 기기 토글, 등록 전 확인을 검사하고 대시보드만 캡처한다. 카메라/미디어 명령의 기존 수용 검사도 유지한다.

연결 보안과 프로토콜의 소유 문서는 [NETWORK.md](NETWORK.md)다. 공개 산출물은 EXE·서명 APK·checksum이며 UX 검증 이미지는 Actions artifact로 분리한다.

## 0.5.0 골격과 범주별 제어

카메라 카드에서 전면/후면(Windows는 물리 장치도)을 고르고 골격 전송을 켠다. 선택은 저장하며 장치가 없으면 안내한다. 영상과 뼈대는 이 기기의 미리보기에만 표시한다. 제스처 안내에서 전체/중간 관리/세밀 조정 동작을 확인한다.

클라이언트 목록 다음의 작업 패널은 실제 등록 작업 선택과 상세 보기를 제공한다. 정확한 값은 키보드로 입력한다. 핀치 모드/조정 값은 사용자가 켜고 고르며 기본 OFF다. Esc·카메라 중지로 해제한다. 확대/이동은 해당 패널 내부로 제한한다. Android 전체 최소화 후에는 앱을 다시 열어 연결해야 한다. 동작 카탈로그와 제한은 [GESTURES.md](GESTURES.md)를 따른다.
