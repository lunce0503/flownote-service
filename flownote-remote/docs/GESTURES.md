# 범주별 제스처와 골격 입력 (0.5.0)

**0.6.0 현재 정책:** 제스처 명령을 중지하고 [터치 리모컨](TOUCH.md)으로 전환했습니다. 서버는 저장된 활성 설정을 무시하며 CLI `gestures on`도 거부합니다. 아래 0.5.x 동작은 과거 구현·합성 엔진 진단의 기록입니다. 카메라 골격 프레임 검증/복구는 호환 진단용으로 유지하지만 명령을 생성하지 않습니다. Android 대시보드에서는 골격/핀치 입력을 제공하지 않습니다.


클라이언트가 MediaPipe Hand Landmarker와 Pose Landmarker로 관절을 추출하고 카메라 위에 뼈대를 그린다. 서버는 관절의 위치와 시간에 따른 움직임으로 아래 명령을 결정한다. Windows는 WebView2, Android는 네이티브 MediaPipe Tasks Vision 1.1.1을 사용한다. 양쪽 안내의 단일 카탈로그는 [`config/scoped-gestures.json`](../config/scoped-gestures.json)이다.

## 사용 순서와 범위

서버와 클라이언트를 모두 0.5.2 이상으로 업데이트한다. 카메라 선택에서 전면/후면을 지정한 뒤 골격 전송을 켠다. Windows에서는 이름으로 물리 카메라도 고를 수 있다. 선택은 저장된다. 후면이나 지정 장치가 없으면 오류를 안내하며 전면으로 자동 대체하지 않는다. 전면 미리보기와 뼈대는 함께 좌우 반전하고 전송 좌표는 반전하지 않는다. 서버가 전면 입력의 좌우 조작 방향을 미리보기에 맞춘다.

서버의 제스처 명령은 기본 OFF다. 켜면 전체 명령은 연결·참여·서버 허용 상태인 클라이언트 전체에, 중간 관리와 세밀 조정은 서버의 제스처 대상에 적용한다. 기기 행의 사용 토글로 참여를 멈출 수 있다. 정밀 수치는 키보드가 기본이다. 음량 0–100%, 확대 50–200%, 가로·세로 위치 -100–100%를 입력하고 적용한다.

핀치는 사용자가 **핀치 조정 허용**과 조정할 값(음량/확대/위치)을 직접 선택했을 때만 동작한다. 모드마다 250ms 집기를 유지해 준비한다. 손을 놓거나 추적이 끊기거나 한 손/양손 구성이 바뀌면 다시 준비해야 한다. Esc, 카메라 중지, 연결 종료로 해제한다. 전체 몸짓은 핀치보다 우선한다. 음량 요청은 한 번에 최대 2%p, 확대는 0.88–1.12배, 이동은 축당 8% 이내이며 연속 명령 간격은 최소 120ms다.

전체 화면은 **Flownote Remote 앱 창**을 뜻한다. 다른 프로그램 창·운영체제 마우스를 조작하지 않는다. 확대·이동은 앱 안의 선택한 작업 패널에만 적용한다. Android는 최소화로 백그라운드에 가면 카메라와 연결을 중지하므로 복원 제스처로 앱을 깨울 수 없다. 사용자가 다시 열고 저장된 서버에 연결해야 한다. Windows는 최소화 상태에서도 명시적으로 켠 카메라를 유지한다.

작업 목록에는 같은 사용자·같은 데이터 경로의 Linux 서버에 연결한 실제 Codex CLI `voice` 세션만 자동 등록한다. 계정 인증과 실제 WebRTC 연결이 완료돼야 나타난다. 20초마다 갱신하고 정상 종료 시 제거하며, 비정상 종료 후에는 최대 65초와 2초 검사 간격 뒤 제거한다. 서버 재시작 후에도 음성 세션의 다음 갱신으로 복구한다. `--native` 터미널 내부 세션은 관찰하지 않으므로 자동 등록하지 않는다. 현재는 작업 선택·포커스·상세 보기이며 임의 에이전트 실행/종료/일시 중지 기능은 없다. Windows 서버에는 이 Linux 소유자 소켓의 세션이 자동 등록되지 않는다.

Android 음량은 기기의 실제 단계로 반올림한다. 키보드 값의 반복 적용은 같은 가까운 단계를 유지하며, 작은 핀치 변화량은 서버에서 누적한다. 화면에는 요청 수치와 다를 수 있는 실제 OS 적용 값을 표시한다. 수동 소리 버튼·외부 음량 변경·카메라 중지·설정/참여 변경 시 미세 변화량 누적을 초기화한다.

## 데이터와 판정

`skeleton.frame`은 최대 16KiB, schemaVersion=1, 증가하는 sequence, 크기, facing(front/back/external), detectionThreshold, precisionMode, pose(0/33점), hands(0–2손×21점)를 보낸다. 관절은 정규화된 x/y/z이며 자세 관절에는 실제 visibility도 넣는다. 손 모델은 관절별 visibility를 제공하지 않아 생략한다. 생략 기본값은 좌표를 사용할 수 있다는 표시이며 모델 확률이 아니다. handedness의 좌/우 분류 확률을 추적 확률로 사용하지 않는다.

클라이언트는 서버가 알린 최소 신뢰도를 실제 탐지/존재 모델 옵션에 적용한다. 서버는 더 낮은 기준의 입력을 차단하고 전체 동작의 어깨·팔꿈치·손목 visibility를 다시 검사한다. 기본 최소 신뢰도 80%, 유지 400ms, 재실행 간격 1200ms다. 관찰이 750ms 넘게 끊기면 유지 시간을 다시 센다. 정적 동작은 풀기 전 한 번만 실행한다. 몸/손이 잘려 있거나 어두우면 명령을 추정해 실행하지 않는다.

서버는 JPEG·base64 영상 필드, 이전 `camera.frame`, 알 수 없는 관절 필드, 비정상 좌표/손 중복/역전된 sequence를 거부한다. 영상은 클라이언트 메모리의 분석·미리보기와 QR 판독에만 사용한다. 골격도 신체 움직임 데이터이므로 신뢰한 서버에만 연결한다. 서버는 골격 기록을 파일로 보관하지 않는다. 한 프레임씩 응답을 기다리며 지연된 프레임을 누적하지 않는다. 실제 처리 속도는 기기 성능에 따라 달라진다.

기존 설정 화면의 7개 손 모양 매핑은 합성/로컬 진단 호환용이다. 실제 네트워크 제스처에는 위 범주 카탈로그를 사용한다. 최소 신뢰도·유지 시간·재실행 설정은 새 골격 판정에도 적용한다.

## 검증

Core 검사는 합성 관절로 11개 동작·유지·해제·추적 손실·전면 좌우·수치 제한을 검사한다. Network 검사는 실제 TLS/WSS로 전체 배포·대상 격리·실제 응답·중복/일시 중지·원본 영상과 잘못된 스키마/sequence 거부를 검사한다. Windows/Chromium 및 Android 장치 검사는 공개 이미지에서 실제 손 모델의 21개 관절과 골격 그리기를 확인한 뒤 합성 몸 자세로 명령 전달을 별도 확인한다. 카메라 선택·중지·QR 경로는 브라우저 가상 카메라와 Android Camera2로 검사한다. 사람의 전체 몸/양손 동작·거리·조명·다양한 물리 카메라 품질은 실기기 수용 검증이 필요하다.

### 카메라 미리보기 직후 연결 끊김 수정 (0.5.2)

상체만 촬영하면 보이지 않는 발 관절의 추정 좌표가 범위를 벗어날 수 있다. 이런 프레임은 제외하고 연결과 다음 프레임 수신을 유지한다. `⋯ → 연결 정보와 기록` 또는 서버 CLI stderr의 `골격 프레임 제외 [landmark_out_of_range]`에서 원인을 확인한다. 모든 프레임이 거부되면 전신/손이 잘 보이도록 카메라 거리와 구도를 조정한다. 잘못된 데이터로 제스처를 실행하지 않는다.

재현 검사는 고정 공개 pose.jpg의 상체 영역(.4,.3,.2,.3)을 480×640으로 처리한 실제 모델 출력과 TLS 세션을 연결한다. 같은 데이터가 0.5.1에서 연결을 끊고 0.5.2에서 프레임 거부 후 정상 제스처·heartbeat·같은 세션의 수동 제어로 복구되는지 검사한다. Android는 실제 후면 카메라 토글→네이티브 모델→미리보기→연결 유지와 잘못된 프레임 후 수신 복구를 함께 검사한다. Windows는 WebView의 불량 프레임 제외 후 카메라 허용 상태와 다음 정상 프레임을 검사한다.
