# Apple Pencil 도구 전환과 기기 저장 기반 동기화

- 요청일: 2026-10-21 (Asia/Seoul)
- 실행 담당: `application manage` / `flownote 앱 관리`
- 세션: `01a04858-b6df-7613-91da-c92a37955657`
- 상태: 구현·정적 검증 완료. cloud staging·production과 네이티브 앱 릴리스 검증 진행 중이며 최종 ID는 `logs/report/`에 기록한다.

## 현재 동작과 목표

기존 [기기 전용 공간](../../product-specs/device-only-workspace.md)은 동기화 OFF 시 서버 자료와 분리된 빈 공간을 열고, ON 시 자동 업로드·병합하지 않았다. 1.2.0에서는 OFF 전에 기존 서버 자료·지원 자산·기준 revision을 기기에 보관하고, 오프라인 편집 후 ON 때 3-way 조정한다. 기존 기기 전용 자료도 유실하지 않는다.

[iOS/iPadOS 앱](../../product-specs/ios-ipados-testflight.md)은 WKWebView 기반이다. 1.2.0 네이티브 로컬 Expo 모듈이 `UIPencilInteraction`의 Pencil 본체 탭을 받고, 신뢰된 내부 origin의 웹 캔버스에 고정 이벤트를 전달해 지우개와 직전 도구를 전환한다. 화면 더블 탭·임의 웹 메시지와는 연결하지 않는다.

## 영향 범위와 최소 경로

| 영역 | 기존 구현/계약 | 변경 목적 |
| --- | --- | --- |
| iOS 앱 | `flownote-mobile/components/installed-web-app.tsx`, iOS 엔트리·Expo 설정 | 네이티브 Pencil 이벤트 수신과 신뢰된 캔버스 전달 |
| 캔버스 | `Canvas.tsx`, `Toolbar.tsx`, `useCanvasPointerInput.ts`, `usePersistence.tsx` | 도구 전환과 오프라인 저장·재동기화 |
| 기기 저장 | `deviceMode.ts`, `deviceStorage.ts`, `deviceTransport.ts`, `deviceWorkspace.ts` | 기존 자료 스냅샷, 계정별 저장, 전환 상태, 재시도 |
| 노트·플래너 | 노트 초안·저장 큐, 플래너 저장 모델 | 동일한 OFF/ON 의미와 충돌 방지 |
| API | 기존 revision·mutation ID·409 계약 | 원자적 적용과 중복 업로드 방지; 필요한 경우만 확장 |
| 배포 | 웹 staging-first, 기존 앱별 릴리스 | 웹·네이티브 버전 호환 및 실제 배포 |

## 구현 순서

1. 최신 운영 배포 소스와 공유 작업 트리의 차이를 확인하고 기존 수정·생성물을 보존한다. 세션의 최근 완료 내용과 현재 제품 문서를 기준으로 시작한다.
2. Apple 공식 SDK와 현재 Expo 빌드 경로에서 `UIPencilInteraction` 적용 방법을 확인한다. 지원 Pencil의 두 번 탭으로 펜/지우개를 전환하고, 시스템 선호 동작을 지원할 수 있으면 따른다. 필기 중 제스처·손바닥·기존 포인터 처리를 해치지 않는다. 브리지는 허용된 고정 이벤트만 전달하며 임의 코드·URL·파일 접근을 열지 않는다.
3. OFF 전에 노트·캔버스·폴더·플래너 및 필요한 이미지의 스냅샷과 기준 revision을 영속 저장한다. 저장 실패·용량 부족이면 성공으로 표시하거나 빈 공간으로 전환하지 않는다. OFF 중 편집·삭제·재시작 복구는 기기 저장으로 수행하고 앱 데이터 API/소켓 송수신을 중단한다.
4. ON 시 인증과 최신 서버 revision을 확인하고 공통 기준본을 이용해 변경분을 조정한다. 무관한 항목 변경은 함께 반영한다. 새 문서·폴더·자산의 ID 매핑과 참조, 삭제 tombstone, 재시도 멱등성을 보장한다. 완료 전 대기 변경을 삭제하지 않는다. 기존 `device-` 자료와 초안은 안전하게 이전한다.
5. 같은 항목의 실제 충돌에는 공통 기준 이후 의미 있는 편집량이 더 큰 버전을 우선한다. 본문 전체 길이 또는 시간만으로 판정하지 않는다. 노트·캔버스·플래너별 비교 규칙과 동률 규칙을 명시한다. 선택되지 않은 내용도 기기에 복구 가능한 사본으로 보존하고 삭제 의도를 처리한다.
6. 제품 동작 소유 문서와 버그 기록, 검증·배포 보고서를 갱신한다. 기존 동기화 분리 정책 설명은 정정한다.

## 검증과 완료 기준

- Pencil 이벤트와 도구 전환, 권한·origin 경계 및 중복 리스너 해제를 검증한다. iPad WebKit 에뮬레이션과 실제 Pencil 하드웨어 검증을 구분해 기록한다.
- 서버 자료가 있는 상태에서 OFF → 자료와 이미지 유지 → 편집·재시작 → ON → 다른 기기에서 결과 확인을 staging에서 실행한다.
- 양쪽 동시 수정, 비중복 수정, 더 많이 진행된 버전 우선, 동률, 삭제, 자산 실패, 저장 용량 부족, 네트워크 단절·재시도, 로그인 만료, 계정·환경 분리를 검증한다.
- 영향받는 프로젝트의 기존 lint/typecheck/build 및 필요한 단위·클라우드 E2E를 통과시킨다. 로컬 앱 서버와 production 데이터 테스트는 사용하지 않는다.
- 웹은 `node scripts/deploy-cloud.mjs release <target>`의 staging 검증 후 같은 소스를 production에 반영한다. 앱은 iOS/iPadOS TestFlight 새 빌드의 실제 완료·제출·처리 상태까지 확인한다. 공통 동기화 변경이 적용되는 Windows·Android도 기존 배포 채널로 갱신하고 업데이트 경로를 검증한다.
- 완료 보고에는 실제 버전, 빌드/배포 ID, 다운로드·테스트 채널, 검증 결과와 미확인 하드웨어 항목을 포함한다. 빌드 접수 또는 백그라운드 시작만으로 릴리스 완료라고 보고하지 않는다.

## 사용자 승인 범위

사용자는 구현과 `application manage` 인계 및 앱 배포를 명시 요청했다. 통상적인 구현·검증·staging/production 배포·기존 앱 채널 릴리스는 해당 요청 범위 안에서 수행한다. 실제 외부 계정 접근이나 필수 자격 증명이 없으면 그 장애와 필요한 조치만 정확히 알린다.
