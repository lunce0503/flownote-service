# 노트 저장·화면 이동 복구 계획

상태: 2026-10-19 isolated snapshot 구현 후보 작성. Go·cloud·채택 검증 대기. 작성: 2026-10-18.
운영에 반영한 계약·소비자·검증은 [Blog 코드맵](blog.md)과 [Markdown 실행 계획](../../exec-plan/completed/2026-10-19-blog-markdown-workspace.md)에서 추적한다. 아래 진단은 변경 전 근거다.

이전 통합 실행 상태는 [MVP 안정화 실행 계획](../../exec-plan/active/2026-10-18-mvp-stabilization.md)에서 관리한다.

## 문제와 근거

`BlockNote.tsx`는 본문 변경을 700ms 뒤 저장한다. 컴포넌트 cleanup은 저장·제목·재시도 타이머를 제거하지만 대기 내용을 영속화하지 않는다. `pagehide`와 `beforeunload`의 비동기 flush는 앱 내부 라우트 이동이나 프로세스 종료 시 완료를 보장하지 않는다. 현재 대기 스냅샷은 메모리에 있다.

따라서 빠른 화면 이동, 저장 실패 후 새로고침, 모바일 앱 종료에서 아직 서버에 저장되지 않은 입력을 잃을 위험이 있다. 코드 검토로 확인한 위험이며 운영 사용자 데이터 유실을 재현한 것으로 기록하지 않는다.

## 목표와 범위

사용자가 입력한 본문과 제목은 서버 저장 확인 또는 명시적 폐기 전까지 복구할 수 있어야 한다. 영향 대상은 `flownote/src/widgets/BlogWidget/BlockNote/`, `entities/blog/`, 인증 종료 처리 및 신규 cloud E2E다. 기존 Canvas의 IndexedDB 초안 패턴을 먼저 확인하고 노트별 작은 저장 모듈로 적용한다.

## 최소 구현

1. 노트별 저장 큐와 화면 수명을 분리한다. 로컬 스냅샷에는 사용자 ID, 노트 ID, 기준 서버 revision, 로컬 변경 순서, 제목·본문, 갱신 시각을 둔다.
2. IndexedDB에 최신 스냅샷을 기록한다. 로컬 저장 실패·용량 초과 시 복구가 가능하다고 표시하지 않고 오류와 안전한 내보내기/복사 등 가능한 다음 행동을 안내한다.
3. 화면 이동 시 최신 본문·제목을 큐에 반영한다. teardown 직전 async 요청만 실행하는 방식에 의존하지 않는다. 한글 조합 중 마지막 입력과 제목 debounce도 포함한다.
4. 재진입 시 같은 사용자·노트의 초안만 읽는다. 서버와 일치하면 정리하고, 서버가 변경됐으면 초안·서버본을 보존하며 복구/서버본 사용 선택을 제공한다. 충돌 상태에서 자동 재저장으로 원격 변경을 덮어쓰지 않는다.
5. ack된 스냅샷과 현재 로컬 변경 순서를 비교한다. 이전 저장 응답 때문에 더 최신 초안을 삭제하거나 저장됨으로 표시하지 않는다.
6. 로그아웃·계정 전환·노트 삭제 시 해당 사용자의 초안 정리 정책을 구현한다. 미저장 입력을 버리는 동작에는 명시적인 안내가 있어야 한다. 다른 계정에서 초안을 조회·복구하지 못한다.

## 계약과 UX

- 기존 `POST /api/notes`의 `revision`, `client_id` 계약은 유지한다. 초안에는 세션 토큰을 저장하지 않는다.
- 상태는 변경됨, 기기에 보관됨, 저장 중, 서버에 저장됨, 저장 실패, 복구/충돌 확인 필요를 구분한다. 기기 보관과 서버 저장을 같은 성공으로 표시하지 않는다.
- 복구 확인·오류 안내는 키보드와 모바일에서 접근할 수 있어야 한다. 새로고침·탭 종료 시 브라우저 경고는 보조 수단으로만 사용한다.
- 완전한 오프라인 노트 앱, 자동 다자 문서 병합, 새 편집기 도입은 제외한다.

## 완료 기준과 검증

- 본문 입력 후 700ms 이내 앱 내부 화면 이동 → 복귀 시 마지막 입력이 남는다.
- 제목 입력 후 800ms 이내 이동, 한글 조합 직후 이동을 각각 확인한다.
- staging API 실패를 브라우저에서 주입한 뒤 편집·새로고침·복구하면 최신 입력이 보존된다. 로컬 앱 서버는 사용하지 않는다.
- 저장 A 진행 중 변경 B가 생겨도 A ack로 B 초안이 지워지지 않는다.
- 서버 revision이 달라진 초안 복구와 계정 전환에서 덮어쓰기·다른 사용자 노출이 없다.
- 초안 순서·정리·오류 처리는 의미 있는 단위 테스트로, 화면 이동·새로고침은 신규 cloud E2E로 검증한다.
- 명령: `cd flownote && yarn verify`, 관련 단위 테스트 및 신규 `e2e-cloud` spec. 실제 명령·결과를 실행 계획에 기록한다.
