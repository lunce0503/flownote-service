## 인계 절차

1. 변경된 기능의 소유 문서·소스·검증·웹 배포 결과를 구체적으로 준비한다. 앱 버전·서명·배포 이력은 최신 기록을 확인한다.
2. 기존 세션에 사용자 원문, 플랫폼 범위, 소스 위치, 네이티브 보완 사항, 검증·완료 기준을 전달한다. 명시된 앱 배포 요청을 같은 작업에 대한 재승인 대기로 바꾸지 않는다.
3. 제공되는 세션 메시지 도구를 우선 사용한다. 도구를 사용할 수 없어 CLI 재개를 이용한다면 해당 세션이 작업 중인지 먼저 확인해 중복 실행을 피한다. 새 대체 세션을 임의로 만들지 않는다.
4. 수신 응답뿐 아니라 실제 소스 검토·구현·검증 도구 활동을 확인한다. 인계 직후 결과 없이 종료되면 남은 작업을 같은 세션에서 재개하고, 실행 중인 세션에는 중복 CLI 실행을 만들지 않는다. 전송 접수, 빌드 접수, 웹 배포를 앱 릴리스 완료로 표시하지 않는다.
5. 실행 담당은 앱별 기능·파일 선택/저장/내보내기·기존 업데이트 경로를 검증하고 기존 채널로 릴리스한다. 웹 변경은 staging-first 절차로 동일 소스를 production에 반영한다. 공유 작업 트리의 다른 변경을 되돌리거나 누락하지 않는다.
6. 버전·빌드/배포 ID·배포 채널·테스트 결과·남은 물리 기기 확인을 `logs/report/`에 남긴다. iOS는 EAS build FINISHED, 제출과 Apple 처리/테스트 그룹 상태를 구분한다. Windows·Android는 실제 배포 파일과 기존 설치에서의 업데이트 경로를 확인한다.

## 2026-10-24 전공서 책장 인계 이력

Android·iOS/iPadOS·Windows에서 [전공서 책장](../product-specs/textbook-library.md)을 검증·보완해 앱 릴리스한다. 웹 검증·배포 기준은 [웹 작업 결과](../../logs/report/2026-10-24-0033-textbook-library-web.md)다. PDF·읽기 기록의 서버 동기화는 별도 기능이며 이번 앱 배포 요청만으로 자동 확장하지 않는다. 현재 기기 보관 범위는 앱 UI와 기록에서 명확하게 유지한다.

특히 웹 최대 PDF 100MiB와 iOS 기존 내보내기 8MiB 제한을 대조한다. 파일 선택·영속 보관·재시작·원본 내보내기·계정 분리를 실제 네이티브 계약에 맞게 보완한다. 큰 파일을 지원하기 위해 브리지의 origin·스키마·파일 종류·크기·경로 검증을 무력화하지 않는다. 실제 기기 미연결 검증은 에뮬레이션과 구분한다.

이 인계의 실행 결과와 실제 앱/웹 배포 상태는 [전공서 책장 앱 릴리스 기록](../../logs/report/2026-10-24-0745-textbook-library-app-release.md)이 소유한다. 검증 완료 플랫폼과 남은 실기기 확인을 구분한다.


## 2026-10-26 작업 공간·책장·캔버스 인계

[실행 계획](../exec-plan/active/2026-10-26-workspace-library-ux.md)의 여섯 요구사항 전체를 유지한다. 회색 저장 중/단순 체크·배경 없음, Android/iOS 펜 접촉 중 커서 숨김·큰 지우개 원, 책장 원본/메타/단어장의 클라우드 연결과 선택 사전·읽기 도구/세부 메뉴, 노트·캔버스 통합 목록, 기본 실시간 Markdown 편집, 캔버스 전체 화면 버튼 제거가 모두 완료 기준이다.

배포 대상은 `library`이며 main(Flyway V22) → canvas(library API) → api(경로/본문 제한) → web을 staging-first로 같은 소스로 배포한다. 웹만 배포하면 새 책장 계약이 깨지므로 축소하지 않는다. 책장 소유권·화면/서버 계정 불일치·100MiB 해시·다른 기기의 메타/원본/단어장·삭제 tombstone·OFF/ON·텍스트 드래그·실시간 편집/IME·원본/초안 보존을 실제 클라우드에서 확인한다. 네이티브 실행 소스가 같으면 기존 설치본이 새 웹을 받는 것을 확인하고 새 바이너리 출시로 과장하지 않는다. 실패하는 새 요구사항을 제거해 기존 검사만 통과시켜 완료하지 않는다.
