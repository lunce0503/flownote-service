# 제품 관점

## 제품 의도

Flownote는 작업, 노트, 캔버스, 에이전트, 소셜, 주식 관리를 한 로컬 통합 환경에서 다루는 생산성 앱이다. 핵심 방향은 사용자가 학습과 작업 흐름을 기록하고, 에이전트가 그 맥락을 읽어 다음 행동을 돕는 것이다.

## 주요 사용자 흐름

- 계정 생성과 로그인 후 개인 데이터 사용
- 작업과 반복 시간표 관리
- 노트 작성과 폴더/카테고리 정리
- 캔버스 기반 드로잉 필기와 이미지 업로드
- 에이전트 대화를 통한 노트/작업 맥락 정리
- 소셜 톡방과 메시지 관리
- Yahoo Finance 기반 주식 자산과 차트 확인(개발 중, 메뉴 비노출)
- Expo 모바일 앱에서 계정, 작업, 노트, 에이전트, 캔버스를 네이티브 화면으로 사용

## 기능 공개 단계

- `AI/flownote-agent`의 학습·평가·도구 호출 코드를 [연구 모듈](../research/flownote-agent/README.md)로 편입했다. 노트·작업 에이전트는 [제품 사양](product-specs/note-task-agent.md)과 [실행 계획](exec-plan/active/2026-10-14-flownote-agent-integration.md)에서 추적하며 실제 API·품질 검증 전에는 제공자를 활성화하지 않는다.
- IDLE의 개발 환경 계획은 Flownote의 개발 작업 공간으로 편입한다. 프로젝트·에이전트 실행·변경 검토·데스크톱 편집·모바일 제어를 기존 노트·작업·Remote와 연결한다. 현재는 계획 단계이며 [제품 사양](product-specs/development-workspace.md)과 [실행 계획](exec-plan/active/2026-10-14-idle-integration.md)에서 추적한다.
- `Magic`, 나사 퍼즐, 밴픽, 주식은 개발 중 기능이다. 라우트는 개발 확인을 위해 유지하지만 일반 탐색 메뉴에는 노출하지 않는다.
- 개발 중 기능은 검증이 완료된 뒤 `capabilityManifest.tsx`의 `stage`와 `nav`를 변경해 공개한다.

## 제품 원칙

- 기능은 첫 화면에서 바로 사용 가능해야 한다.
- 데이터가 비어 있을 때도 다음 행동을 명확히 보여준다.
- 에이전트 기능은 사용자 데이터의 실제 맥락을 읽고 행동 후보를 제안해야 한다.
- 모바일은 데스크톱 기능의 축소판이 아니라 작은 화면에서 완료 가능한 흐름이어야 한다.
- 외부 API 기능은 실패해도 앱의 기본 데이터 관리 기능을 깨지 않아야 한다.

## 성공 기준

- 사용자는 작업, 노트, 시간표, 캔버스, 주식 정보를 새로고침 후에도 유지할 수 있다.
- 주요 화면은 인증 실패, 데이터 없음, 서버 오류를 명확히 표시한다.
- 에이전트가 읽을 수 있는 데이터 형태가 안정적이고 문서화되어 있다.
- 모바일에서 운영 게이트웨이 URL, Expo 실행, Railway 웹 테스트 흐름이 문서와 일치한다.
