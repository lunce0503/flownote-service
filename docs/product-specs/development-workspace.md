# 개발 작업 공간

상태: 2026-10-14 계획 편입. 아래는 목표 동작이며 현재 제공되는 기능으로 표시하지 않는다.

## 목표

IDLE의 편집기·에이전트 실행·모바일 제어 계획을 Flownote 안에서 관리한다. 사용자는 프로젝트를 선택하고 목표를 실행하며 코드 변경을 검토하고 결과를 노트·작업과 연결한다.

단계·검증·의사결정의 소유 문서는 [IDLE 편입 실행 계획](../exec-plan/active/2026-10-14-idle-integration.md)이다.

## 사용자 흐름

1. Flownote에 로그인하고 자신에게 허용된 프로젝트를 선택한다. 프로젝트가 없으면 등록 조건과 연결할 워커를 안내한다.
2. 목표를 입력하고 전달할 노트·작업을 선택한다. 모델에 전달할 맥락과 실행 제한을 확인한다.
3. 실행 화면에서 단계·도구 결과 요약·진행 상태를 보고 취소할 수 있다. 연결이 끊겨도 다시 접속해 저장된 이력을 본다.
4. 승인이 필요한 작업은 도구·대상·변경 내용·만료를 표시한다. 승인 또는 거절 뒤 최신 상태를 확인한다.
5. 실행이 끝나면 결과·오류·검증·변경 파일과 diff를 검토한다. patch가 만들어졌다는 사실과 원본 반영·운영 배포 성공을 각각 표시한다.
6. 사용자가 선택한 노트·작업에 요약과 실행 참조를 남긴다. 관련 없는 개인 데이터를 자동으로 전달하지 않는다.

첫 단계는 기존 실행 결과의 조회부터 제공하고, 수동 실행·승인·patch 채택은 다음 단계에서 연다.

## 화면과 클라이언트

- 웹: 프로젝트 목록, 목표 입력, 실행 이력·상세·이벤트, 파일/diff 검토. capability는 개발 단계로 등록하고 검증 후 메뉴를 공개한다.
- 데스크톱: 프로젝트 폴더 선택, 파일 탐색·Monaco 다중 탭·저장, 터미널·Git 변경·실행 패널. 저장 전 외부 변경 충돌을 알리고 미저장 편집을 보존한다.
- 모바일: 기존 Flownote 모바일에서 목표·상태·취소·승인·diff를 작은 화면에서 처리한다.
- Remote Android/Host: 기존 기기 등록·WSS·PTY 셸을 유지한다. 개발 실행 조회와 직접 PC 셸 조작의 연결 대상·권한을 화면에서 구분한다.

## 데이터와 API

사용자별 Project/Run/Event/Approval/Artifact를 기준으로 조회한다. HTTP 제어·이벤트 스트리밍은 기존 Flownote 게이트웨이와 세션 인증을 사용하며 예정 경로는 `/api/development/**`다. 아직 구현된 API는 아니다.

Run 상태는 대기, 실행, 승인 대기, 성공, 실패, 취소, 제한 초과다. 재시도는 새 실행으로 남긴다. 파일/diff/승인/event cursor도 실행 소유권을 검증한다. 실패 큐·원본 로그를 그대로 클라이언트에 공개하지 않는다.

원본 소스 반영은 기준 소스 지문을 확인하고 충돌이면 다시 검토한다. 기존 피드백 자동 배포는 정해진 정책을 유지하며 수동 개발 실행이 그 배포 권한을 자동으로 갖지 않는다.

## 빈 상태·진행·오류

- 등록 프로젝트 없음: 허용된 저장소와 워커 등록 절차를 안내한다.
- 워커 연결 없음: 실행할 수 없는 이유와 마지막 연결 상태를 표시한다. 작업이 시작됐다고 표시하지 않는다.
- 진행 중: 단계와 경과 시간, 한도, 취소 상태를 표시한다. 모델 내부 추론·비밀값·터미널 원문은 기본 표시하지 않는다.
- 승인 대기: 대상과 검토할 변경을 보여준다. 만료·거절·취소 후 다시 승인할 수 없다.
- 연결 단절: 마지막 이벤트 순서부터 복원한다. 복원할 이력이 없으면 재조회 필요를 안내한다.
- 실행 실패·제한 초과: 종료 원인과 검토할 산출물을 남긴다. 자동 무한 재시도를 하지 않는다.
- 원본 변경: patch 적용을 차단하고 새 기준으로 다시 생성·검토하도록 안내한다.
- 부분 배포 실패: 기능 성공으로 표시하지 않고 단계별 영수증과 기존 롤백 절차를 연결한다.

## 검증

사용자별 프로젝트·실행·승인·파일·artifact 격리, 목표 실행·취소·제한·실패, 이벤트 순서·재접속, stale patch 차단, 노트·작업 연결을 검증한다. 데스크톱은 실제 설치·파일 저장 충돌·PTY 종료, 모바일은 실기기 입력·회전·백그라운드 복귀를 포함한다.

구현 전에는 개발 메뉴·기능을 공개하지 않는다. 단계별 검증·릴리즈 결과는 실행 계획과 보고서에 남긴다.
