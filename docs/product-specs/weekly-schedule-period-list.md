# 주간 일정 기간 리스트

## 목표

하나의 반복 일정에 서로 다른 요일과 시간 구간이 필요할 때 일정 추가 화면을 반복해서 열지 않고, 한 번의 입력 흐름에서 여러 기간을 지정한다.

## 사용자 흐름

1. 플래너의 주간 탭에서 `일정 추가` 또는 요일 헤더를 누른다.
2. 공통 일정 이름과 색상을 입력한다.
3. 기간 리스트의 각 행에서 하나 이상의 반복 요일과 시작·종료 시간을 선택한다.
4. `기간 추가`로 행을 늘리거나 삭제 아이콘으로 불필요한 행을 제거한다. 최소 한 행은 유지한다.
5. `기간 N개 저장`을 누르면 각 기간이 같은 이름과 색상을 가진 반복 일정으로 저장된다.

요일 헤더에서 추가를 시작하면 첫 기간은 해당 요일을 선택한 상태로 열린다. 기존 일정 한 건을 선택해 수정할 때는 저장된 데이터 단위에 맞춰 기존처럼 한 개의 요일 집합과 시간 구간만 편집한다.

## 데이터와 API

- 기간 한 행은 기존 `ScheduleItemInput` 한 건으로 변환한다.
- 공통 필드인 제목, 분류, 색상, 메모, 활성 상태는 모든 기간에 복사한다.
- 각 기간은 기존 `POST /api/schedule-items` 요청으로 순차 저장한다. 데이터베이스 스키마와 API 계약은 변경하지 않는다.
- 여러 기간 중 하나가 실패하면 같은 저장 시도에서 먼저 생성된 일정에 `DELETE /api/schedule-items/{id}`를 요청해 부분 저장을 되돌린다.
- 종료 시간이 시작 시간보다 이르면 기존 규칙대로 자정을 넘기는 일정으로 취급한다. 시작과 종료 시간이 같은 구간은 허용하지 않는다.

## 빈 상태, 로딩, 오류 상태

- 제목이 없거나, 기간이 없거나, 기간에 선택된 요일이 없거나, 시간이 비어 있거나 같은 시간이면 해당 기간 번호를 포함한 오류를 표시한다.
- 저장 중에는 저장 버튼을 비활성화하고 `저장 중…`을 표시한다.
- 저장 실패 시 입력 폼과 기간 리스트를 유지해 사용자가 값을 수정해 다시 시도할 수 있게 한다.

## 검증

- 서로 다른 요일·시간을 가진 기간 두 개 이상이 한 번의 저장으로 주간 보드에 표시된다.
- 요일 헤더에서 추가한 첫 기간에 선택한 요일이 반영된다.
- 기간을 추가·삭제해도 다른 기간의 값이 바뀌지 않는다.
- 기존 일정 수정과 삭제 동작은 이전과 동일하게 유지된다.
- 모바일 너비에서 요일, 시간 입력, 삭제 버튼이 겹치거나 잘리지 않는다.
