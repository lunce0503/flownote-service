# 전공서 책장 — 웹 첫 버전

작성: 2026-10-24 (Asia/Seoul). 상태: 웹 첫 버전 운영 배포 완료. [검증·배포 기록](../../logs/report/2026-10-24-0033-textbook-library-web.md).

## 범위와 흐름

사용자가 PDF와 제목을 등록하는 개인 전공서 책장이다. `/library`에서 세로로 쓴 책등을 분야별 선반에 꽂고, 분야 칸막이·검색·즐겨찾기로 찾는다. 책등 선택 시 PDF 첫 페이지 표지를 먼저 보여주고 읽기를 명시적으로 시작한다. PDF 첫 페이지를 표지로 사용하므로 실제 표지와 다를 수 있다.

웹 첫 버전의 PDF·분류·읽던 페이지·페이지 책갈피는 현재 브라우저의 계정별 IndexedDB에 저장한다. 서버 업로드나 기기 간 동기화는 하지 않는다. UI에서 저장 범위를 알리고 원본 PDF 내보내기를 제공한다. 사이트 데이터 삭제나 브라우저 저장소 회수 시 사라질 수 있어 원본 파일을 보관해야 한다. 기존 캔버스의 임시 PDF 읽기와 다른 영속 책장이며 기존 기능은 유지한다.

## 작은 화면의 읽기

- 페이지 폭 맞춤을 기본으로 하고 확대·여백 줄이기와 좌우 단 집중 보기를 제공한다.
- 좌우 단 모드는 원본을 재배치하지 않고 선택 영역만 확대한다. 두 단이 아닌 책은 전체 페이지를 쓴다. 수식·그림은 원본 페이지의 배치를 유지한다.
- 한 번에 한 페이지만 렌더하고 페이지 이동·숫자 이동·읽던 위치 복원·페이지 책갈피를 제공한다. 목차 자동 추출·OCR·본문 재배치·AI 해설·필기 레이어는 후속 범위다.
- 도구는 가로 넘침 없이 줄바꿈하고 화면 자체의 수평 스크롤과 확대된 PDF 영역의 스크롤을 분리한다.

## 데이터와 보안

`features/library`가 메타 모델, PDF 처리와 IndexedDB 저장을 소유하고 `pages/LibraryPage`가 UI를 소유한다. 기존 capability 매니페스트에 지연 로드된 보호 라우트를 추가한다. 사용자·원본 파일·토큰은 로그에 쓰지 않는다.

- PDF 최대 100MiB, 확장자·타입·실제 PDF 헤더를 확인한다. 파싱 실패/암호 PDF/용량 부족은 성공으로 표시하지 않는다.
- 기존 PDF.js와 번들 worker를 사용하며 `isEvalSupported=false`, 임의 URL·스크립트·외부 링크 실행 없음. 원본 파일은 렌더러에 Blob 데이터로 전달한다.
- 메타와 원본 추가·삭제는 원자적 트랜잭션이다. 원본은 WebKit File/Blob 저장 오류를 피하기 위해 트랜잭션 전에 ArrayBuffer로 변환한다. 읽기 상태 갱신은 파일을 다시 쓰지 않고 현재 메타에 적용해 탭 간 손실을 줄인다. 계정 전환 시 이전 비동기 응답은 적용하지 않는다.
- 표지는 제한된 크기의 생성 이미지이며 책장 조회에서 전체 PDF를 읽지 않는다. 문서/렌더 task와 canvas 메모리는 해제한다.

## 검증·출시

책 등록·표지·이어 읽기·분류 이동·즐겨찾기·페이지 책갈피·새로고침·계정 격리·비정상 PDF·저장 실패를 검사한다. 390px 스마트폰, iPad WebKit, 데스크톱과 키보드 이동을 클라우드 staging에서 검증한다. `yarn verify`와 모델 테스트 후 `node scripts/deploy-cloud.mjs release web`으로 staging E2E를 통과한 동일 소스만 production에 배포한다. 백엔드 실행 코드 변경은 없다.

## 다음 단계

## 앱 1.3.0 저장 계약

Android·iOS/iPadOS·Windows도 `/library`를 같은 앱 메뉴에서 연다. 원본 PDF와 읽기 기록은 현재 앱 프로필의 계정별 IndexedDB에 보관한다. 앱을 다시 시작하거나 같은 앱 ID로 업데이트해도 저장소를 지우지 않는다. 앱 삭제·사이트 데이터 삭제·OS 저장소 회수에 대비해 원본을 별도로 보관한다. 서버 책장 동기화는 이 릴리스 범위에 포함하지 않는다.

iOS 1.3.0은 고정 HTTPS origin의 PDF 요청만 256KiB 단위로 확인 응답을 주고받아 최대 100MiB를 Expo 파일 캐시에 기록한다. 사용자 확인 후 공유 메뉴의 ‘파일에 저장’으로 내보내며 완료·취소·오류·페이지 이동에서 임시 파일을 정리한다. UUID, 정확한 필드, 순서, 총 크기, PDF 헤더를 검증하며 다른 형식의 기존 8MiB 제한은 유지한다. 이전 iOS 앱은 작은 파일의 기존 경로를 사용하며 큰 PDF 내보내기는 앱 업데이트가 필요하다.

Android는 기존 파일 선택기로 선택한 content URI만 받으며 PDF를 256KiB씩 private cache에 기록한 뒤 Android 저장 위치 선택기로 출력한다. 100MiB·헤더·전송 순서를 검증하고 부분 파일을 정리한다. JavaScript interface를 추가하지 않는다. 다른 형식의 기존 내보내기 제한은 유지한다. Windows는 Electron의 기본 다운로드 스트림과 저장 대화상자를 사용한다.

100MiB는 파일 크기 상한이다. PDF 렌더링·IndexedDB 원자적 보관에는 추가 메모리와 저장 공간이 필요하며 기기 상태에 따라 등록이 실패할 수 있다. 웹 WebKit 및 브리지 에뮬레이션 검증과 실제 iPad 파일 선택·공유 시트 검증을 구분해 릴리스 보고서에 남긴다.

1. 웹 책장·PDF 읽기 흐름 검증.
2. 사용성 확인 후 책·분류·진행도·주석의 서버 계약과 기존 동기화 ON/OFF 정책 연결. 대용량 원본과 오프라인 다운로드의 보관 정책을 먼저 정한다.
3. Android·iOS·Windows의 파일 선택·저장·내보내기·업데이트 경로를 물리 기기에서 확인하고 앱 채널별 릴리스. 웹 출시를 세 앱 검증·배포 완료로 간주하지 않는다.
