# 노트 Markdown 작업 공간

기존 기준: 2026-10-19 구현·staging 47개 E2E·운영 배포 완료. 2026-10-26 통합 목록·실시간 편집 갱신도 staging 107/107 및 운영 배포를 완료했다. [최종 릴리스 기록](../../logs/report/2026-10-26-2049-workspace-library-app-release.md)에서 증거를 확인한다.

## 목표와 사용자 흐름

노트을 Markdown으로 작성하고 캔버스와 일관된 간결한 작업 공간에서 폴더·노트를 탐색한다. 목록을 열기 위해 모든 본문을 기다리지 않으며 선택한 노트만 불러온다.

1. `/blog`와 `/canvas` 목록 진입은 같은 노트·캔버스 작업 공간을 연다. 본문 없이 메타데이터부터 보여주며 기존 문서 URL은 유지한다.
2. Windows 탐색기처럼 폴더를 펼쳐 노트를 보고 선택한다. 선택 노트·펼친 폴더·경로가 일치한다.
3. 새 노트의 기본 편집기는 Markdown 입력을 즉시 서식으로 렌더링한다. 원문·미리보기·나란히 보기는 명시적으로 선택할 수 있다.
4. 저장 상태를 확인하고 다른 노트를 열었다가 돌아와도 마지막 입력을 복구한다.
5. 기존 구조화 문서는 원본을 유지한 채 열고, 사용자가 명시적으로 선택할 때 Markdown으로 전환한다.

## 화면과 탐색

- 기존 캔버스의 밝은 배경, 단순한 테두리, 아이콘·버튼 규칙과 설치 앱 테마를 따른다. 기존 카드 대시보드 대신 왼쪽 탐색과 오른쪽 문서 작업 영역을 사용한다.
- 상단은 사이드바 토글, 경로/제목, 저장 상태, 새 노트·폴더 및 필요한 파일 동작으로 구성한다. 장식용 통계·중복 헤더는 추가하지 않는다.
- 트리는 폴더·노트를 구분하고 접기/펼치기, 현재 선택, 이름 변경, 생성·이동·삭제를 제공한다. 삭제는 폴더 제거와 노트 삭제를 구분하고 기존 노트를 조용히 함께 삭제하지 않는다.
- 첫 버전은 현재 `category → folder → note` 구조를 실제 트리로 표현한다. 임의 깊이의 하위 폴더는 `parent_id`·순환/소유권 검사·삭제 계약이 필요한 후속 확장으로 분리하며, 실제로 저장하지 않는 중첩을 가능한 것처럼 표시하지 않는다.
- 새 노트는 선택한 폴더에서 생성한다. 이동은 드래그 외에도 키보드·터치에서 사용할 메뉴를 제공한다. `.md`를 표시명으로 사용할 수 있지만 서버 ID와 실제 호스트 파일 경로를 혼동하지 않는다.
- 모바일은 사이드바를 닫을 수 있는 drawer로 전환하고 편집 영역을 확보한다. 390px, 820px, 1440px에서 가로 넘침·키보드·터치 영역을 검증한다.

## Markdown과 기존 데이터

- 새 문서의 기준은 Markdown 원문이다. 제목, 목록/체크리스트, 표, 인용, 코드 블록, 링크·이미지, 수식의 작성·미리보기를 지원한다. 기존 렌더러·설치 라이브러리를 먼저 재사용한다.
- Markdown 원문과 미리보기는 같은 스냅샷을 사용하며 미리보기 렌더러는 필요할 때 지연 로드한다. raw HTML과 실행 가능한 URL을 허용하지 않는다.
- 기존 BlockNote JSON은 여는 것만으로 저장하거나 변환하지 않는다. 전환 전 원본을 복구 가능한 형태로 보존한다.
- 이미지·수식·표·그리기·지원하지 않는 블록의 변환 범위를 테스트한다. 표현할 수 없는 내용은 원본 보기/다운로드 경로와 안내를 제공하고 조용히 버리지 않는다.
- 저장 형식은 `content: {format:"markdown",version:1,markdown:string}`으로 구분하고 서버가 `legacy_original`을 보관한다. 기존 JSONB의 형식 표식을 원자적으로 검사하므로 새 migration은 추가하지 않는다. 예전 클라이언트가 Markdown 문서를 빈 BlockNote 배열로 덮어쓸 수 없도록 서버에서 요청을 검증한다. 상세 계약은 [설계·실행 계획](../design-docs/blog/markdown-workspace-plan.md)을 따른다.
- 최신 입력의 초안·화면 이동·서버 충돌·계정 전환은 [노트 저장 복구 계획](../design-docs/blog/note-save-recovery-plan.md)의 데이터 보존 기준을 적용한다.

## 로딩과 오류

- 폴더·노트 메타 목록은 본문 없이 병렬로 불러오고, 목록과 본문 로딩/오류를 분리한다.
- 한 노트의 본문 장애가 다른 노트의 목록·선택을 막지 않는다. 빠른 연속 선택에서 이전 응답이 현재 문서를 덮어쓰지 않는다.
- 목록·본문 캐시는 사용자별로 분리하고 logout·변경 알림에 맞춰 무효화한다. 실패를 빈 문서로 저장하지 않는다.
- 초기 화면은 본문·미리보기·레거시 편집기 전체를 기다리지 않는다. Canvas와 같은 메타 목록 → 선택 문서 본문 구조를 사용한다.
- 속도 평가는 같은 staging 환경·합성 데이터·warm/cold 조건으로 Canvas와 비교한다. 측정 전 지연 개선 수치를 확정하지 않는다.

실행 단계·실제 측정·검증·배포 상태는 [노트 개편 실행 계획](../exec-plan/completed/2026-10-19-blog-markdown-workspace.md)에서 추적한다.


색상·탐색·명칭은 [공통 작업 공간 디자인](../design-docs/canvas/workspace-explorer-design.md)을 따른다. 흰 문서·베이지 탐색/선택·검정 글자와 동작이 기준이며 다크 모드는 따뜻한 무채색이다.


## 실시간 편집 갱신 (2026-10-26, 운영 반영 완료)

기존 Tiptap 3.20 기반에 같은 버전의 Markdown·수식·표·체크리스트 편집 기능을 연결한다. 기본 화면은 입력 즉시 제목·강조·목록·수식 등을 렌더링하는 편집기다. Markdown 원문이 저장 기준이며 `content.format/version/legacy_original` 계약과 기기 초안·저장 큐·충돌 복구를 유지한다. 열기·포커스·초기 파싱만으로 원문을 자동 저장하지 않는다. 실제 입력·서식 조작부터 저장하고 복구/원문 모드의 외부 변경을 중복 저장하지 않는다.

실시간 편집기는 문서를 선택할 때 지연 로드한다. HTML을 실행하지 않고 링크·이미지 URL은 기존 safeMarkdownUrl 기준으로 제한하며 KaTeX trust는 false다. 한글 조합, Markdown 바로 입력, 원문과의 전환, 재로드 후 서식/내용, 정확한 원문 내보내기를 검증한다. 관련 실행·운영 반영은 [현재 계획](../exec-plan/active/2026-10-26-workspace-library-ux.md)을 따른다.

편집기별 Markdown 파서를 분리하며 체크리스트 뒤의 제목·강조·한글도 저장과 재로드에 보존한다. Tiptap 3.20의 빈 inline token 오류 보완은 [버그 기록](../../logs/bugs/2026-10-26-live-markdown-task-roundtrip.md)을 따른다.

## 생성·편집 도구·수식 개선 (2026-10-28, 검증 중)

- 새 노트는 별도 브라우저 prompt 없이 제목 없음 문서를 바로 생성하고 제목을 편집한다. 통합 목록과 열린 노트에서 모두 제공한다. 폴더 연결만 실패하면 생성된 문서를 열고 미분류에서 다시 이동하도록 알린다. 요청 중 중복 생성을 막고 계정 변경 후 이전 결과를 열지 않는다.
- 주 동작은 접근 가능한 이름/툴팁이 있는 아이콘이며 세부 설정은 세로 세 점으로 연다. 원문·나란히 입력 방식과 서식은 편집 중에만 펼치는 도구 창에 둔다. 미리보기에는 입력 도구를 표시하지 않고 기존 자동 서식 안내 문구를 제거한다. 내보내기·저장 재시도·서버본/초안·원본 보존 동작은 세부 설정에 유지한다.
- 한 줄 중간 편집에서 자체 입력의 늦은 React echo로 문서를 재설정하지 않는다. Windows IME 조합 중에는 문서/선택을 재설정하지 않고 조합 종료 후 최종 글자를 저장한다. Home/End/삭제/줄 추가/선택 교체/undo/redo와 저장/재로드를 검증한다.
- `$ 수식 $`는 인라인, 독립된 `$$` 사이 여러 줄은 블록 수식으로 입력한다. 원문과 실시간 편집의 저장 형식은 동일하다. 코드와 이스케이프 구분자는 변환하지 않는다. 수식 내 `\fr`, `\sq` 등 입력에 추천을 제공하며 클릭/Tab으로 삽입하고 Esc로 접는다. 수식 추가/수정은 설치 앱에서도 동작하는 편집창에서 수행하며 KaTeX trust=false를 유지한다.

실행과 배포 증거는 [현재 계획](../exec-plan/active/2026-10-28-note-editing.md)에서 추적한다. 이전 회귀 통과를 이번 변경의 완료 증거로 사용하지 않는다.

인접한 inline 수식 노드는 실제 사용자 편집의 Markdown 직렬화 snapshot에만 공백 경계를 넣어 `$a$ $b$`로 구분한다. live 문서와 커서/선택은 바꾸지 않으며 주변 문자·수식 값·code/literal dollar와 열린 원문을 보존한다. 저장·재로드 뒤 각 inline 값과 미리보기의 실제 KaTeX 개수 및 오류0을 함께 검증한다.
