# 앱 동기화와 기기 전용 모드

## 사용 방법

설치형 iOS/iPadOS 1.1.0(4), Android 1.1.0, Windows 1.1.1 앱에서 **전체 → 설정 → 앱 동기화**를 끄고 전환을 확인한다. 앱은 현재 계정의 기기 전용 작업 공간을 연다. 설정은 계정별·앱 저장 공간별로 유지되며 다른 기기의 설정은 바뀌지 않는다. 일반 브라우저 웹에는 이 스위치를 표시하지 않는다.

처음에는 빈 공간이다. 서버 자료를 지우거나 기기에 자동 다운로드하지 않는다. 노트/폴더, 캔버스/폴더/이미지, 플래너의 할 일·시간표·일기를 기존 편집기로 작성하면 기기의 IndexedDB에 저장한다. 서버 저장과 Socket.IO 변경 수신/발행은 모두 중지한다. UI는 기기 전용 상태를 표시하며 저장 transaction 성공 전에는 저장 성공으로 표시하지 않는다.

동기화를 다시 켜면 원래 서버 작업 공간으로 돌아온다. 기기 자료는 보존되지만 서버에 자동 업로드·병합하지 않는다. 다시 끄면 기존 기기 자료를 사용한다. 다른 기기로 옮길 노트는 `.md`로 내보내는 등 사용자가 직접 파일을 옮겨야 한다.

## 저장 및 보안 경계

- 기기 저장 DB는 현재 웹 환경 origin에 속하며 계정 ID별 레코드로 구분한다. 인증 정보/쿠키를 자료에 저장하지 않는다. 기기의 잠금과 앱 접근을 대체하는 암호화된 금고는 아니다.
- 클라우드/기기 초안 DB와 캔버스 재시도 큐를 분리한다. 기기 전용 리소스 ID는 `device-`로 시작하며 클라우드 API 전송 경계에서도 차단한다.
- 일반 API는 로컬 어댑터가 지원 계약만 처리한다. 미지원 요청/오류를 네트워크로 재시도하지 않는다. Canvas HTTP/socket 저장 및 이미지 업로드도 로컬 처리하고 실시간 연결을 만들지 않는다.
- 전환은 설정 화면에서 확인 후 새 페이지로 이동하며 기존 실시간 소켓을 닫는다. 전환 전에 서버가 이미 받은 요청은 되돌릴 수 없으므로 먼저 저장 상태를 확인한다. 설정 변경은 다른 열린 창에도 새로고침으로 반영한다.
- 기기 모드는 캐시된 로그인 사용자로 개인 공간을 열며 세션 검사 API를 호출하지 않는다. 서버 모드로 돌아오면 실제 HttpOnly 세션을 다시 검사한다. 만료되었다면 재로그인한다.
- 기기 모드 로그아웃은 로컬 사용자 표시만 지우고 기기 자료는 남긴다. 네트워크가 차단된 상태라 서버 세션을 폐기하는 요청은 보내지 않는다. 공유 기기에서는 백업 후 앱/사이트 데이터를 별도로 정리해야 한다.

## 제한과 백업

기기 전용은 완전 오프라인 앱 최초 실행을 보장하지 않는다. WebView 화면·JS 모듈 다운로드, 네이티브 앱 업데이트에는 인터넷이 필요할 수 있다. 앱 삭제, 사이트 데이터 삭제, OS 저장 공간 정리로 기기 자료가 사라질 수 있다. AI·소셜·주식·관리 기능·프로필 변경·피드백은 서버 모드에서 사용한다. 외부 이미지나 외부 네트워크 기능은 기기 작성 자료의 일부로 자동 다운로드하지 않는다.

설정의 **기기 자료 JSON 백업 내보내기**는 현재 계정의 원본 데이터 묶음을 내보낸다. iOS 공유 계약과 맞춰 8MB 이하를 지원한다. 자동 가져오기/병합 UI는 아직 없으므로 복구 자료 보관용이며, 노트는 별도로 `.md` 파일로도 내보낼 수 있다. 8MB를 넘는 큰 자료는 개별 파일로 보관해야 한다. 백업에는 개인 작성 내용이 있으므로 안전한 위치에 보관한다. 기기 캔버스 이미지는 PNG/JPEG/WebP/GIF 20MB 이하를 data URL로 저장하며 IndexedDB quota 실패를 숨기지 않는다.

## 검증 기준

백업은 기기 작업 공간의 저장 완료 원본을 대상으로 한다. 편집기에 미저장 입력이나 복구 초안이 있다면 먼저 저장/복구를 확인하거나 해당 입력을 `.md`/초안 JSON으로 내보낸다. 자동 저장 대기 중에 앱을 강제 종료하면 마지막 변경이 저장되지 않을 수 있으므로 저장 상태를 확인한다.

`deviceWorkspace.test.mjs`, `deviceMode.test.mjs`와 기존 초안/저장 큐 단위 테스트를 실행한다. `e2e-cloud/device-only.spec.ts`는 Chromium과 iPad WebKit에서 서버 트래픽 부재, 재시작 복원, 계정 분리, 전환 취소/저장소 차단/quota 실패, 서버 불변과 재전환 후 로컬 원본 보존을 검사한다. 실제 iPad의 OS 저장소 회수·앱 종료/재설치와 공유 시트는 별도 기기 확인 대상이다.
