# 앱 오프라인 작업 공간과 재동기화

## 목표와 사용자 흐름

설치형 iOS/iPadOS, Android, Windows 앱에서 **전체 → 설정 → 앱 동기화**를 끌 수 있다. 끄기 전 현재 계정의 노트·폴더, 캔버스·폴더·이미지, 플래너 할 일·시간표·일기를 기기 IndexedDB에 스냅샷하고 기준 revision을 기록한다. 스냅샷과 자산 저장이 모두 끝나기 전에는 오프라인 전환 성공으로 표시하지 않는다.

OFF 상태에서는 스냅샷 자료를 그대로 보고 편집한다. 일반 데이터 API와 Canvas Socket.IO/실시간 변경 수신·발행은 차단되고, 저장은 계정별 기기 작업 공간에만 반영된다. 앱을 종료하거나 기기를 재시작해도 저장 완료된 내용과 대기 중인 재동기화 계획을 다시 연다. 이전 버전에서 만든 `device-` 문서·초안은 버리지 않고 로컬 작업 공간에 합친다.

다시 ON으로 바꾸면 실제 로그인 세션을 확인하고 최신 서버 자료를 읽어 공통 기준본과 3-way 조정을 수행한다. 서로 다른 필드나 항목의 변경은 함께 반영하고, 새 로컬 ID와 참조를 서버용 UUID로 바꾼 뒤 순서대로 업로드한다. 각 성공 단계의 cursor와 ID 매핑을 저장한다. 실패 후 재시도는 최신 서버 자료로 다시 조정해 이미 적용한 변경과 추가 서버 변경을 확인하며 같은 자원을 중복 생성하지 않는다. 조정 중 다른 창의 로컬 쓰기는 잠시 차단하고 편집기 초안을 유지한다. 모든 적용과 최종 재조회·기기 기준본 저장이 성공한 뒤에만 클라우드 모드로 전환한다.

## 충돌과 복구

- 기준본 이후 한쪽만 바뀌었으면 그 변경과 삭제 의도를 적용한다.
- 양쪽의 서로 다른 필드 변경은 결합한다. 캔버스 요소, 작업 시간 로그, 일기 할 일처럼 ID가 있는 컬렉션도 항목별로 결합한다.
- 같은 값이 양쪽에서 다르게 바뀌면 본문 길이나 시각 하나가 아니라 구조적 변경량을 계산한다. 생성·삭제, 필드 변경, ID 컬렉션의 추가·수정·삭제를 의미 있는 편집으로 센다.
- 변경량이 큰 쪽을 선택하고 동률이면 `updated_at`이 최신인 쪽, 시각도 같으면 기기 쪽을 선택한다.
- 자동 선택으로 사라지는 기준본·기기본·서버본과 선택되지 않은 버전, 점수·선택 이유를 기기 복구 기록에 보존한다. 기록을 개수 기준으로 자동 삭제하지 않고 설정의 JSON 백업에 포함한다. 저장 용량 부족이면 원본과 대기 계획을 유지하며 완료 전환하지 않는다.

이 규칙은 데이터 손실을 줄이는 자동 조정 정책이지 사람의 의미 판단을 완전히 대체하지 않는다. 중요한 충돌은 복구 기록을 확인하고 필요한 내용을 새 문서로 복원한다.

## 데이터와 API 계약

- 작업 공간 schema v2는 현재 자료, 기준 스냅샷, 전환 상태, 마지막 성공 시각·오류, 대기 연산과 cursor, 복구 기록을 계정별로 저장한다. v1 데이터는 읽을 때 v2로 이전한다.
- 클라우드 생성 API의 노트·캔버스·노트 폴더·캔버스 폴더·작업·일정은 클라이언트 UUID를 받을 수 있다. 같은 사용자와 같은 ID의 재전송은 같은 자원으로 수렴하고 다른 사용자의 ID를 가져오지 않는다.
- 조정 중 네트워크 허용은 메모리 안의 명시적 sync scope와 내부 표식 헤더가 모두 있을 때만 적용한다. 표식은 실제 요청 전에 제거한다. 일반 UI 요청은 ON 완료 전까지 계속 로컬 어댑터에서 처리하거나 실패한다.
- 캔버스 이미지는 인증된 캔버스 요소 목록에 연결된 자산을 기존 프록시로 내려받아 data URL로 저장한다. 자산 GET의 기존 공개 URL 계약은 유지한다. 지원 이미지의 누락·부분 다운로드·quota 부족이 있으면 OFF 전환을 중단한다. 로컬 이미지는 캔버스 내용 적용 전에 업로드해 참조를 바꾼다.
- 인증 토큰·쿠키는 작업 공간에 저장하지 않는다. IndexedDB는 앱 origin과 계정 ID로 논리 분리되지만 기기 잠금이나 암호화된 금고를 대체하지 않는다.

## 오류·제한과 백업

오프라인 스냅샷 중 서버·자산·저장소 오류가 발생하면 기존 클라우드 모드를 유지한다. ON 조정 중 인증 만료나 네트워크 오류가 발생하면 로컬 자료와 cursor를 남기고 OFF 상태를 유지해 재로그인·재시도가 가능하게 한다. 앱 데이터/사이트 데이터 삭제, 앱 삭제, OS 저장 공간 회수로 로컬 자료와 복구 기록이 사라질 수 있다.

OFF 직전에는 서버 스냅샷과 기존 클라우드 편집기 초안을 대조한다. 현재 계정 노트에 서버와 다른 미저장 입력이 있거나 현재 계정 캔버스에 미저장 초안·서버 저장 재시도 작업이 있으면 전환하지 않는다. 기존 클라우드 모드와 초안을 그대로 보존하고 해당 편집기의 저장·복구 또는 내보내기를 안내한다. 서버와 내용이 이미 같은 노트 초안은 지연된 저장 확인으로 보고 전환을 막지 않는다. 계정이 다른 노트와 현재 계정 캔버스 ID에 속하지 않는 큐는 메시지에 노출하거나 전환 차단에 사용하지 않는다.

OFF 상태에서도 WebView 화면·JS 번들의 최초 다운로드와 네이티브 업데이트에는 인터넷이 필요할 수 있다. AI·소셜·주식·관리·프로필 변경처럼 스냅샷 계약 밖 기능은 사용할 수 없다. 외부 URL 이미지는 자동 보관 대상이 아니다.

설정의 **기기 자료 JSON 백업 내보내기**는 현재 자료, 기준본, 대기 계획, 복구 기록과 별도 편집기 초안·캔버스 재시도 큐를 포함한다. ON 시작과 최종 전환 전에 미저장 초안을 확인하며, 미저장 입력이 있으면 기기 모드를 유지하고 해당 편집기의 복구·저장 또는 내보내기를 안내한다. 자동 조정 대상은 저장 완료된 기기 자료이며 미저장 초안을 조용히 버리지 않는다. iOS 공유 계약에 맞춰 8MiB 이하만 내보내며 자동 가져오기 UI는 아직 없다. 개인 작성 내용이 포함되므로 안전한 위치에 보관한다.

## 검증 기준

단위 테스트는 v1 이전, 기존 `device-` 보존, 스냅샷, 비중복 결합, 변경량 충돌·동률·삭제, ID remap, 재시도 cursor, sync scope를 검증한다. cloud staging E2E는 서버 자료가 있는 OFF → 자료/이미지 유지 → 오프라인 편집·재시작 → ON → 서버 재조회, 양쪽 충돌, 저장 실패와 네트워크 재시도를 검사한다. 실제 OS 저장소 회수·강제 종료와 iPad 공유 시트는 별도 실기기 확인 대상이다.
