# 노트·작업 에이전트

상태: 2026-10-14 연구 코드 편입. 아래 흐름은 서비스 적용 목표이며 아직 제공되는 기능으로 표시하지 않는다.

## 목표

사용자가 허용한 개인 노트·작업 맥락으로 자료를 찾고 정리하며 작업 후보를 만든다. [`research/flownote-agent`](../../research/flownote-agent/README.md)의 학습·평가·도구 호출 코드를 연구 기반으로 사용한다. 구현·선정 상태는 [실행 계획](../exec-plan/active/2026-10-14-flownote-agent-integration.md)에서 관리한다.

## 사용자 흐름

1. 로그인한 사용자가 요청하고 사용할 노트·작업 범위를 선택한다.
2. 지원 도구와 실제 조회 결과로 후보를 만든다. 필요한 날짜·대상·인자가 없으면 다시 묻는다.
3. 변경·삭제는 대상과 내용을 보여주고 서버가 확인 상태·최신 버전을 검증한다.
4. 실제 도구 성공 뒤 결과와 자료 참조를 보여준다. 저장 실패를 성공으로 답하지 않는다.
5. 실행 요약을 선택한 노트·작업에 연결한다. 다른 사용자 데이터나 선택하지 않은 맥락을 자동으로 전송하지 않는다.

노트 검색·읽기·요약·수정, 작업 조회·생성이 초기 연결 대상이다. 관계 저장·알림·웹 조회·export는 실제 기반이 검증된 기능만 제공한다. 연구 도구 14개가 모두 운영 기능이라는 뜻은 아니다.

## 실행과 권한

- 기존 세션 인증과 도메인별 권한을 사용한다. 모델이 보낸 사용자 ID로 권한을 결정하지 않는다.
- 스키마·시간·단계·context 제한, 취소·확인·오류 처리는 실행 계층에서 적용한다.
- 화면에는 실제 도구 단계·결과·오류를 보여주고 내부 추론·모델 제어 토큰은 응답으로 내보내지 않는다.
- 삭제 확인·본문 변경은 서버의 확인 기록·대상·버전을 묶는다. 모델의 `confirm=true`만으로 삭제하지 않는다.
- 외부 모델·웹 조회에 전달할 맥락을 제한하고 사용자 데이터 출처와 결과 근거를 유지한다.

## 개발 작업 공간과의 관계

[개발 작업 공간](development-workspace.md)의 Run/Event/Approval이 구현되면 조회·취소·확인 계약을 공유한다. 프로젝트 shell·patch·배포 권한은 자동으로 제공하지 않는다. 기존 Codex 자동화의 제공자도 유지한다.

Canvas OCR/전사 입력은 검수와 인식 오류 전달을 포함한 별도 단계다. Canvas LoRA 파일럿은 노트 에이전트의 품질 입증 결과가 아니다.

## 빈 상태·오류

- 제공자 비활성: 상태와 기본 노트·작업 기능을 안내한다.
- 자료 없음: 검색 범위·검색어를 다시 선택한다.
- 인자·대상 불명확: 추측해 저장하지 않고 재질문한다.
- 권한 없음·버전 충돌: 변경을 중단하고 재조회·재검토한다.
- 파서 오류·잘못된 도구: 실제 실행을 차단하고 오류를 기록한다.
- timeout·취소·한도: 완료한 작업과 미완료 작업을 구분한다.
- 미지원 알림·export: 성공이라고 표시하지 않고 지원 범위를 알린다.

## 검증과 공개 조건

고정 평가셋에서 기본 모델과 학습 모델의 파싱·도구 이름/인자·다단계 성공·환각·재질문·지연을 비교한다. 실제 API에서 사용자 격리·확인·충돌·중복 변경·취소를 검증한다.

GPU 학습 성공·mock 테스트·낮은 loss만으로 공개하지 않는다. 검증된 제공자와 도구만 capability로 노출하고 staging 검증 후 동일 소스를 배포한다.
